# 按需导出画面 PDF

用于用户想翻阅视频画面、审查编排或留存讲解图示的情况。PDF 是静态画面册，页数由实际内容决定，不把某一次作品的页数当成模板。

1. 已有成片时，从当前认可的成片中取帧；只有预览时，使用同一场景源码、素材和时间轴取帧，不为导出 PDF 额外要求先渲染视频。记录来源版本与取帧时间。
2. 每个讲解单元选择内容完整、入场已经结束的代表状态。遇到后续画面替换早先信息的过程，额外保留有独立解释意义的中间状态，例如公式分项、连乘数值例子、递推的起点与推进过程。避免只取每页最后一帧而漏掉重要步骤，也不机械逐帧打印动画。
3. 按讲解顺序编排，保持画面比例和清晰度。必要时增加目录；页脚标注对应视频时间、小节标题与页码。只有预览时注明时间对应哪一版预览，不把它冒称为最终成片时间。
4. 使用当前环境可用的 PDF 技能或工具生成文件。正文画面不重新排写或改动公式；目录、说明和页脚可另行排版。完整保留图表边界、上下标和脚注，避免截图被页面裁切。
5. 检查页数、页面尺寸、图片是否齐全与时间顺序；将 PDF 重新渲染，查看总览以及公式、密集图表和首尾页的样例，确认字形、清晰度和边界正常后交付。PDF 的页面检查不能替代视频的音画连续审看。

画面、脚本、取帧记录与生成文件归入工作区约定的项目资料目录，不进入技能源码仓库。复用已认可的画面与素材，不为静态导出另做一套风格。

## 可复用导出工具

先由内容和实际动画确定取帧清单，工具只负责取帧、排版和检查，不替代语义选择。尤其不能把过渡中的半透明帧、尚未讲到的空框或每页最后一帧机械收集为完整画面。数学排版沿用成片中的 LaTeX 形式，不在 PDF 中重新用粗体正文抄写。

`scripts/export_visual_pdf.py` 在 macOS 使用已验证的 CoreGraphics/CoreText 后端，无需安装 Python PDF 包或 OCR/推理依赖；需要已有的 `ffmpeg`、`ffprobe` 与 `clang`。其他环境使用可用的 PDF 技能和依赖，不把这个后端说成跨平台工具。输出保持原图比例，加入封面、可选章节目录、时间范围、取帧时间和页码。

```json
{
  "source_video": "完整视频.mp4",
  "title": "讲解画面合集",
  "frames": [
    {"title": "问题与背景", "scene_start": 0, "scene_end": 20,
     "time": 18.5, "state": "完整画面"},
    {"title": "向量屏蔽", "scene_start": 20, "scene_end": 45,
     "time": 29, "state": "屏蔽前"},
    {"title": "向量屏蔽", "scene_start": 20, "scene_end": 45,
     "time": 43, "state": "屏蔽后与缩放"}
  ]
}
```

```bash
python scripts/export_visual_pdf.py --manifest 取帧索引.json \
  --chapters 视频章节.txt --out 画面合集.pdf --check-pages 3,5
```

命令相对技能目录运行，输入和输出应放在项目资料目录。相对视频、图片路径按清单所在目录解析；可用 `--video` 指定当前成片。工具从现有 MP4 直接取图，按视频指纹和时间缓存，不重新编码全片。只有同版预览图片时，不提供视频路径，改为每项设置 `file`，并在清单设置 `duration` 与清楚的 `source_label`（注明预览版本）；不会为了 PDF 先渲染 MP4。

章节 TXT 使用 `HH:MM:SS 章节标题`；也支持已解析为全局秒数的章节 JSON。章节时间应与取帧来源一致。每页图片的比例必须一致，不拉伸图片塞入模板。输出旁的 `_assets` 目录保存图片、清单、生成报告与重新渲染的检查页；图片与 PDF 不进入技能仓库。

交付前打开这些重新渲染的页面，查看中文、公式分式与上下标、密集表格及首尾页，确认方向、清晰度与边界。报告中的 `visual_review: pending` 不代表已经人工检查。若依赖缺失或下载失败，优先复用已验证的本地后端；不要为截图合集反复安装大型推理依赖，也不将页数固定为任何历史作品的数量。
