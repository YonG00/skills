# 推进思考：反例、中间态与制度机制分析清单

> **来源**：Conversation Synthesis Skill v3 — https://www.cnblogs.com/yong2333/articles/22980128
> **覆盖**：第六部分（第 29–35 条）｜ **作用**：把「分析停在表面」的七种塌陷转成可逐条执行的追问动作——每个重要判断问三遍、主动找反例与限制、在二元问题上找中间态、识别系统激励、检查资源是否对称、检查制度建议的副作用、把政策建议落到机制。

## 这份清单怎么用

- 七条不是七种修辞，而是七种**触发条件**：出现「重要判断」「核心判断」「二元问题」「大量个人行为反复出现」「制度分析」「制度建议」「政策建议」时，对应条目立即生效。
- 每条按同一结构执行：**何时触发 → 问什么 → 为什么 → 例子 → 防止的失败模式**。
- 「问什么」中的问题**保留原文措辞**，不要替换成更顺口的说法；替换往往会把问题问软。
- 「防止的失败模式」一栏，原文已直接给出的照抄原文；原文未直接给出的留空（`—`），不补写。
- 本文件只管「继续追问」，不管文章结构；不得据此新增原文没有的规则。
- 「例子」一栏用于说明动作怎么执行：原文自带示例的原样引用，其余为通用示意，仅用于演示动作，不构成模板。

## 29. 每个重要判断问三遍

**何时触发**：任何准备写进文章的「重要判断」。

**问什么**（原文三问，逐问追问）：

1. 依据是什么？——数据、法律、经历、研究还是推演？
2. 所以呢？——它改变了哪个问题？
3. 真正想说什么？——能否说成一句明确的话？

**为什么**：三问分别锁住来源、后果和结论：依据不明则判断无根，答不出「改变了哪个问题」则判断无后果，说不出「一句明确的话」则判断还没成形。三问都过，判断才算想透。

**例子**：写下「这个问题很重要」之后，用三问走一遍——依据是什么（数据 / 法律 / 经历 / 研究 / 推演）？所以呢（它改变了哪个问题）？真正想说什么（能否说成一句明确的话）？走完仍然只落回「这个问题很重要」，就回到上一问继续想。

**防止的失败模式**：如果最终只能写：这个问题很重要。说明还没想透。

## 30. 主动寻找反例和限制

**何时触发**：每个核心判断。

**问什么**：

- 在什么情况下它不成立？

**为什么**：反例不是为了机械平衡。是为了确定结论边界。

**例子**（原文示例）：写下「某种制度通常有利」，继续问：对所有职业都适用吗？是否存在新的风险？成本由谁承担？

**防止的失败模式**：反例不是为了机械平衡。（完整表述：反例不是为了机械平衡。是为了确定结论边界。）

## 31. 遇到二元问题，主动寻找中间态

**何时触发**：讨论自然形成 A / B；进入 / 退出；全部 / 没有；自由 / 控制。

**问什么**：

- 是否存在连续谱？
- 是否存在第三种制度安排？
- 是否只是市场目前没有提供中间产品？

**为什么**：很多有价值的洞见，来自找到 0 和 1 之间的选项。这是一种通用分析方法，不限于任何具体主题。

**例子**：原文列出的四组二元结构（A / B；进入 / 退出；全部 / 没有；自由 / 控制）任取一组，依次问连续谱、第三种制度安排、市场是否只是暂时没提供中间产品。

**防止的失败模式**：—（原文未直接给出）

## 32. 主动识别系统激励

**何时触发**：如果大量个人行为反复出现。

**问什么**：

- 系统正在奖励什么？
- 系统正在惩罚什么？
- 人的行为是不是对激励的适应？

**为什么**：反复出现的行为不应停在「人的选择」上，而要问它在适应什么激励；但必须区分——机制解释 和 已经被数据证明的因果，两者不能混为一谈。

**例子**：面对一种反复出现的行为，先问它被什么奖励、被什么惩罚、是不是对激励的适应；在写下解释之后，再标明这句话目前是「机制解释」，还是有数据支撑的「已经被数据证明的因果」。

**防止的失败模式**：但要区分：机制解释 和 已经被数据证明的因果。

## 33. 制度分析要检查实际资源是否对称

**何时触发**：制度分析中出现「双方都有某项权利」这类纸面表述时。

**问什么**（原文七问）：

- 谁掌握信息？
- 谁承担举证？
- 谁有专业人员？
- 谁熟悉程序？
- 谁能承担拖延？
- 谁承担时间成本？
- 谁更容易放弃？

**为什么**：纸面平等和实际使用能力是两件事。

**例子**：不能只写「双方都有某项权利」，要继续用七问过一遍：谁掌握信息、谁承担举证、谁有专业人员、谁熟悉程序、谁能承担拖延、谁承担时间成本、谁更容易放弃。

**防止的失败模式**：不能只写：双方都有某项权利。／ 纸面平等和实际使用能力是两件事。

## 34. 制度建议要检查副作用

**何时触发**：每提出一种治理、监测、技术或组织方案。

**问什么**：

- 它会不会制造新的问题？

**为什么**：好的方案不仅解决原问题。也要防止新问题变得更糟。

**检查项**（原文，逐项过一遍）：

- 隐私
- 监控
- 形式主义
- 数据造假
- 合规成本
- 权力滥用
- 新的不平等

**例子**：任何监测或治理方案写出来之后，不要停在「它解决了原问题」，逐项检查上面七项，把可能被新造出来的问题写在方案旁边。

**防止的失败模式**：好的方案不仅解决原问题。也要防止新问题变得更糟。

## 35. 政策建议必须尽量落到机制

**何时触发**：任何政策建议。

**问什么**（原文八问）：

- 谁负责？
- 做什么？
- 数据从哪里来？
- 多久一次？
- 谁能看到？
- 如何保护隐私？
- 出现异常以后怎么办？
- 如何避免被游戏化？

**为什么**：越接近执行，建议越有价值。

**例子**：不要只写「应该加强重视」，把这八个问题逐个答出来，答案越具体，建议越接近执行。

**防止的失败模式**：不要只写：应该加强重视。
