## [2.0.0] — 阶段重排（7 → 6）；叙事人称；表格保留；结尾放宽

**规则来源**：一次真实的技术类文章调试（7 阶段全流程跑完，18 轮反馈）。用户回：「我在尝试偏技术方向的文章总结时，遇到一些问题」。

### 修改 1：阶段重排 —— 标题与大纲提到初稿之前

用户原话：

> 「先确定文章脉络，再确定候选标题与子标题这些，再是正文初稿，润色后加链接，最后成稿。」
> 「我的意思是，**先确定大纲，下个阶段才是初稿**。」

旧顺序把「标题候选」放在**最后一个阶段**，导致用户在初稿写到一半时必须打断它。新顺序：

```
1 文章脉络 → 2 标题与子标题 → 3 正文初稿 → 4 润色 → 5 加链接 → 6 成稿
```

- **取消独立的「结尾与问题升级」阶段**（见修改 4）
- **「论证加固」并入阶段 1**：每个判断变化点直接附上反例与限制
- 阶段 2 就要给**每个小标题 2–3 个候选 + 推荐**（用户：「大纲目录，也可以每个子标题也给多个版本供我选择，有推荐，也有候选」），并**当场应用语言风格规则**

### 修改 2：叙事人称 —— 不要把"探索者本人"放在每段中央

用户原话：

> 「另外**不要一直提"我干嘛"**，风格得变下，是我去探索，去深究，但这事没必要一直说。」

**实测**：初稿里「我」出现 **28 次**，几乎每段都以作者的认知动作开头，**四个小标题全是第一人称叙事**：

```
✗ 四、我后来发现，accuracy 和 calibration 根本不是同一个问题
✗ 五、我最开始又把 calibration 和"按概率采样"混在了一起
✗ 六、到这里，我对"模型概率"的理解发生了一个比较重要的变化
```

**提炼的通用规则**：探索感**由问题的递进体现**，而不是由"我去研究了/我发现"体现。含第一人称叙事的段落**不超过全文 1/4**；小标题**不许**用第一人称叙事。

**同时新增「作者提示语」禁令**（模型自己的诊断）：「最初的问题很直接：」「这首先解释了一个容易混淆的地方：」「更值得追下去的是另一个问题。」「这样看，X 并不是最难解释的部分。」——判断法：删掉这句，读者会不会看不懂？不会 → 删。

**语言基调**（写进 `SKILL.md` §七）：**像一个人认真把一个新技术一路查清楚，允许保留疑问和修正，但不把"探索者本人"放在每一段中央。**

### 修改 3：表格保留 —— 守恒要覆盖呈现形式

用户原话：

> 「**之前的聊天内容中，不是有一些表格吗？怎么到文章内容就没有了？**」

**实测**：对话里有一张关键实验表（5 行方法 × Accuracy / ECE / Brier / 平均置信度）。阶段 1 骨架里有 50 行表格，但**初稿阶段表格归零**，被拍平成"RLCD 的表现比普通 outcome RL 更好"这类概括；到后续阶段才被找回。

**根因**：守恒核对只查**内容有没有归属**，没查**形式有没有保住**。归属表写着"进第 3 节"，但没写"以什么形式进"。

**修改**：归属表增加**「以什么形式进」** 列（表格 / 数据点 / 概括 / 列表）；对话里已形成表格结构的资产**默认保留为表格**，拍平必须给理由（维度少于 2 或数据不足以支撑对照）。**形式本身就是信息。**

### 修改 4：结尾放宽 —— 不强制"问题升级"

用户原话：

> 「【**没必要结尾升级吧**】」

上游第 48 条把"问题升级"定为硬性要求（必须回答五问）。**技术类文章尤其不适用**：方法、数据和边界都讲清楚了，再追加一段"下一步该往哪走"往往是硬凑的。

**新规则**：结尾最低要求三条——**不重复 / 收得住 / 给出一个东西**（判断 / 更准确的认识 / 明确还缺什么）。**可选**：确实推进出了新问题才点出来，没有就不要造。

**原文保留**：第 48 条原文仍存档在 `structure-and-style.md`，标注为"（原文，存档）"，下方给出 48-bis 现行做法。

## [1.0.0] — 本地合并版

**变更类型**：以 v3 为主线重组为可执行规范，并补上 v3 缺失的执行方法与静默丢失的规则。

### 合并方式

1. **以 v3 为骨架**（它是唯一完整自洽的一版，19 部分 / 59 条）。
2. **基础版作为存档与核对基线**：全文保留在 `references/base-version.md`，逐条映射到 v3。
3. **v3 的细节规则按主题抽到 `references/`**，`SKILL.md` 只保留可执行主干、硬约束与检查项。
4. 比对中发现的静默丢失**予以恢复并标注来源**（本节末尾）。

### 本仓库原创

| 新增 | 位置 | 说明 |
|---|---|---|
| **对话 → 文章骨架的七阶段方法** | `references/conversation-to-outline.md` | v3 第 13 条只给了"问题链"的**形状**，没给推导过程；第 10 / 20 条反复要求"信息资产不能无缘无故丢"，却没给核对机制。本文件补上：论元抽取（含"用户后续修正覆盖先前表述"的状态机制）→ 问题链重建 → **判断变化点识别** → 章节切分 → 资产归属与**守恒核对** → 中心问题定稿 → 骨架表 |

| **骨架表 + 信息资产归属表** | 同上 | 把 v3 的"不能丢"变成可审计的总数守恒 |

### ★ 基础版 → v3 的静默丢失（本仓库恢复）

逐条比对 17 条基础版规则后，**整条完全缺失的：无**；但查出 **4 处局部静默丢失**。按 `references/skill-maintenance.md` 第十四部分「旧规则 = 保留……即使准备删除，也不应直接删除，应先标记『建议删除：原因……』交给用户决定」，本仓库**先恢复并标注**，同时列为待人工确认。
