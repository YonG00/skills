# 知乎提问挖掘（Zhihu Question Mining）

把一段**口语稿、录音转写、随笔笔记或长文档**，拆成**多个可以单独发布的知乎提问**。

每个提问交付两样东西：

1. **标题**——一句话，精准、有力、有讨论空间
2. **问题描述**——保留本人的说话方式，把困惑讲清楚，但不提前下结论

**它不是什么**：把稿子改写成文章；把一个大问题包装得漂亮；替你想出你没想过的问题；替你在知乎提问框里自动发布。

本文件是可执行规范。**转写核对见 `references/transcript-fidelity.md`**；核心方法见 `references/topic-splitting.md`；标题规则见 `references/title-craft.md`；描述风格见 `references/description-style.md`；真实案例见 `references/worked-example.md`。

## 0. 七条不可违背的元原则

| 原则 | 含义 | 防止的失败模式 |
|---|---|---|
| **专有名词先核对** | 口述稿是转写来的，人名/产品名/公司名可能听错。核对前不得把它当事实基础 | 基于一个不存在的名字建出一整个假话题（FM-8） |
| **不只找提问** | **想法、点子、主张、方案也是产出**。填不出矛盾句式 ≠ 没价值 | 好点子因为"不是问题"被扔进未采用清单（FM-11） |
| **一个提问 = 一个核心矛盾** | 不是一段录音的摘要，是一个能独立成立的冲突 | 把好几件事塞成一个"大问题"（FM-4） |
| **差异不大就合并** | 粒度拿不准时**合**，不是拆。任务要的是能发出去的提问，不是尽可能多的提问 | 拆得太细，用户反复要求合（FM-5） |
| **保住说话的那个人** | 第一人称、口语、具体例子、真实困惑、**他说的动机**，一个都不能丢 | 整理感太重、文绉绉、像专栏文章（FM-1、FM-6）；替他补充没说过的话（FM-10） |
| **具体对象前置** | 标题用产品名/作品名/真实场景切入，抽象留给描述 | 标题太泛、像行业报告题目（FM-2、FM-3） |
| **不写成预设答案** | 困惑要保留开放性，不要把自己的判断当前提 | 像在自问自答，吸引不到真正懂的人（FM-7） |

> 前两条在 1.1.0 / 1.2.0 加入，与原有五条同级。**「不只找提问」是 1.2.0 新增**——它改变了整个任务的产出定义：**不只是提问，还有想法。**

## 一、先理解稿子，不要马上写

### 1.1 转写核对（第一件事，不能跳）

口述稿通常是**语音转写**的产物。一个听错的专有名词会**长出一整个假话题**，而且看起来毫无破绽。

真实事故：稿里的「**ZEV** 第一系统模型」实为 **Jev**——模型基于一个不存在的名字建了完整话题，还分析了它的训练方式。另一个更危险：「**DeepMind**」实为 **DeepSeek**，两个都是真公司，**完全不触发警觉**。

**动作**：通读时对每个**专有名词**（人名 / 产品名 / 公司名 / 作品名 / 机构名 / 数字 / 专业术语）问一句——**这个词在这个句子里合不合理？**

- **能联网 → 搜一下**，核对「名称 + 语境」是否匹配
- **搜不到 / 多个候选 / 语境对不上 → 直接问用户**，不要猜
- 改动过的每一处，**在汇报表里写明「原名 → 改后 → 依据」**

完整方法（三类可疑信号、处置动作表、禁止事项）见 `references/transcript-fidelity.md`。

### 1.2 内容分三类（不是两类）

**这一步做不好，后面全是把一篇长文切成几段。**

口语稿的特点是：**发散、重复、话题来回跳、没有小标题**。不能按段落切，要按**矛盾或主张**切。完整方法见 `references/topic-splitting.md`。

**契约**：输入一份稿子，输出——**三类**清单、合并/拆分判定记录、粒度检查结果。

| 类别 | 判据 | 产出 |
|---|---|---|
| **提问** | 填得出「我看到 A，但按理说 B」——**有落差** | 知乎提问（标题 + 描述） |
| **想法 / 点子** | 填不出落差，但填得出**一个主张、观察、设想或做法** | 想法条目（一句话 + 展开 + 去向） |
| **未采用** | 两者都填不出（纯背景 / 纯情绪 / 重复 / 转写噪声） | 未采用清单（附理由） |

> ⚠️ **中间那一类不能省。**「不是一个问题」**不等于**「没有价值」。早期版本只有"提问 / 未采用"两分类，于是主张、观察、点子全被扔进未采用清单——**那是在丢东西**。
>
> 用户原话：「不仅要找问题，**不是问题，想法、点子这些也算，也需要提出来**」。

**六步摘要**：

| 步 | 做什么 |
|---|---|
| **A 标记** | 通读全篇，标出五类东西：**具体场景/不爽**（触发点）、**已有的疑问句**、**用户判断**、**事实与引用**、**重复与岔路** |
| **B 切单元** | 按**场景切换**和**矛盾对象切换**切分。同一个矛盾的不同段落 → 合并 |
| **C 分三类** | 每个单元过一遍：有落差 → 提问；有主张没落差 → **想法/点子**；两者都没有 → 未采用 |
| **D 提炼** | 提问填「我看到 A，但实际是 B」；想法填成**陈述句**（见 1.4） |
| **E 定粒度** | 默认**存疑则合**；拆分必须有「答案体系不同」支撑（见 1.5） |
| **F 产出** | 三类清单 + 判定记录 |

### 1.3 提炼核心矛盾（用于提问）

每个话题单元必须能填出这个句子：

> **我看到 / 我遇到的是 ______，但按理说 / 大家都说应该是 ______。**

例：

- 「微信打电话能直接用蓝牙耳机，**但** AI 对话反而不行。」
- 「组织追求去个人化，**但** 优秀作品又高度依赖个人。」
- 「我的体验是刚起床特别难做决定，**但** 有些人遇到新问题就是能很快反应过来。」

**填不出这个句式的话题，不要写。** 它多半只是资料、感慨或背景，不是一个能独立成立的提问。

> ⚠️ **但不要就此丢掉它。** 先过 §1.4——它有可能是想法或点子。

### 1.4 提炼想法与点子（填不出矛盾的那一类）

**「不是一个问题」不等于「没有价值」。** 主张、观察、点子、方案、原则都算产出，都要提出来。

完整的判据、句式与交付格式见 `references/ideas.md`。要点：

**五类算想法**：

| 类型 | 句式 |
|---|---|
| **主张** | 「我认为 X 应该……」「X 其实不是……」 |
| **观察** | 「我发现 X 和 Y 有关系」「越……反而越……」 |
| **点子** | 「可以做一个 X」「如果能 X 就有用」 |
| **方案 / 做法** | 「如果要做 X，应该先……」「比较靠谱的顺序是……」 |
| **标准 / 原则** | 「判断 X 的标准是……」「不该只看 X，要看 Y」 |

**提炼三条要求**：

1. **用陈述句**，不用疑问句——疑问句是提问的地盘
2. **主语是想法本身**，不是「我觉得」——「我觉得 Agent 便宜」→「Agent 的成本优势只在某些环节成立」
3. **保留本人的措辞和具体名词**——不要把「获客、物流和退货」抽象成「履约成本结构」

**仍然算未采用的**：纯背景信息 / 纯情绪感慨（只有情绪没有主张）/ 转写重复 / 别人的话且本人没接话 / 没讲完就跳走的。

> **判据**：问一句「这句话里有没有一个属于他的主张？」有 → 想法；没有 → 未采用。

**同一段里既有提问又有想法时，分别提取，不要合并也不要二选一。**

### 1.5 决定拆到什么粒度

**默认倾向：存疑则合。** 本任务要的是**能发出去的提问**，不是尽可能多的提问。

真实记录：某次初划分给出 **12 个话题**，用户在后续三轮要求合并 **3 次**，要求拆分 **0 次**，最终收敛到 **9 个**。**模型在这个任务上的系统性偏差是"拆得太细"。**

**拆分的唯一正当理由：答案体系不同**——它们需要不同的人、不同的知识背景来回答吗？

| 成立（该拆） | 不成立（该合） |
|---|---|
| 「打卡制度怎么设计」vs「大脑能不能被复制」 | 「30 岁做 AI 到 50 岁职业价值怎么变」vs「普通本科能不能走到 CTO」——同一批职场人就能一起答 |

**「另外」「还有一个问题」不构成拆分理由。** 口语稿里这是说话人的**口头连接词**，几乎每换一口气都会说。这个信号**只看最终描述，不看原稿**。

两个方向的检测：

| 检测 | 症状 | 修正 |
|---|---|---|
| **过度合并** | **最终描述**里出现「另外」「还有一个问题」**且**两部分需要不同的人回答；或描述里有**两个互不相干的触发场景** | 拆开 |
| **过度拆分** | 缺具体场景支撑 / 描述不足三句 / 共享同一触发场景 / **两问的回答者高度重叠** / **核心矛盾句式只差一个变量** | **合回去** |

**合并或拆分后必须重新给标题。** 合并产生的是一个**新对象**，标题要重新给（可复用其中一个，也可重写）。真实事故：合并 T5+T6 后产出里写成 `**T5 + T6｜合并描述**`，**占位标签被当成了标题**。

**重要**：如果用户已经认可了一套话题划分，**不要继续往下拆**。用户说「原来分出的 7 点挺好的，内容再润色就行」时，改动范围就只是标题和描述的文字——不要重新划分话题。这是最常见的一种越界。

## 二、标题：从具体痛点切进去

**一句话原则**：标题要让**具体的东西**先出场，把抽象留给描述。

### 2.1 五条判据

1. **具体对象优先**——产品名、作品名、真实场景，比抽象概念更抓人
2. **反差结构**——「A 能，B 为什么不能」「都这么厉害了，为什么还这么麻烦」
3. **动词和人话**——「蟑螂到底怎么弄最有效」而不是「如何系统治理蟑螂」
4. **允许一点情绪**——「难道人类到现在还没一套靠谱办法吗？」是好的
5. **一行以内，不标题党**——不夸张、不制造虚假悬念、不用「浅析/探析/成因」

### 2.2 三条真实反例（都是被用户退回的原话）

| ✗ 被退回 | 原因 |
|---|---|
| 「AI 到底怎样才能真正融入日常生活，而不是有问题时才拿手机出来问？」 | **太泛，像行业报告题目** |
| 「为什么很多作品一旦失去"灵魂人物"，整个味道就变了？」 | **抽象层级提得太早**，把《凡人》这个最能吸引人点进去的具体对象藏掉了 |
| 「公开分享自己的想法，会让个人受益，还是在主动放弃"信息差"？」 | 用「信息差」这种词，**不像普通人会这么问** |

### 2.3 同一话题的三次修改（真实记录）

| 版本 | 标题 | 问题 |
|---|---|---|
| 一稿 | 为什么 AI 助手不能像微信电话一样通过蓝牙耳机直接对话？ | 太长、太书面 |
| 二稿 | 为什么 AI 助手不能像微信电话一样直接用蓝牙耳机对话？ | 仍然没有反差 |
| **定稿** | **为什么微信打电话能直接用蓝牙耳机，AI 对话反而不行？** | 「能 / 反而不行」构成反差，口语 |

完整对照见 `references/title-craft.md`。

## 三、描述：保住说话的那个人

**这是整个任务里最容易做坏的一步。** 口语稿转成书面语时，绝大多数模型会不自觉地"整理"，结果读起来像专栏文章、像行业报告，就是不像一个真人在知乎上提问。

### 3.1 要保留什么

- **第一人称**，从具体场景开始（时间、地点、动作）
- **短句、一句一段**的节奏
- **口语连接词**：我就在想 / 所以我更想问的是 / 就跟…一样 / 这个事我一直挺奇怪的
- **具体名词**：真实的产品名、作品名、地名、数字
- **情绪的痕迹**：有点烦、挺奇怪的、我也想不通
- **困惑的开放性**——保留「可能」「我也说不好」「不知道是不是」

### 3.2 只做三件事

1. **去重复**——同一句话说了三遍，留一遍
2. **理顺逻辑**——把来回跳的顺序摆正
3. **让别人能快速看懂你在问什么**

### 3.3 不要做（每一条都对应一次真实退回）

- ❌ **不要"整理"**：不要加小标题、不要编号分点、不要提炼"核心观点"、不要总结
- ❌ **不要拔高**：不要把「刚起床脑子没开机」写成「晨间认知功能激活滞后」
- ❌ **不要替用户下结论**：用户说「我怀疑」，不要写成「事实证明」
- ❌ **不要写成预设答案**：把自己的判断写成提问的前提，会让真正懂的人不想答
- ❌ **不要用书面套语**：进行、从而、基于、综上所述、值得注意的是

> **判断标准**：把描述念出来，像不像这个人**真的会在知乎上这么问**？不像，就是整理感太重了。

### 3.4 结尾格式

描述的最后，落到一个**明确的疑问句**（可加粗），后面可以跟 1–3 个追问。

```
所以我更想问的是：

**这种快速判断、快速解决问题的能力，到底能不能练？**

如果能练，平时应该怎么练？
```

完整 before/after 见 `references/description-style.md`。

## 四、交付格式

**分两个区块**——提问和想法不要混在一起：

```
## 一、知乎提问

### 1. <标题>

<问题描述，第一人称，多段>

---

### 2. <标题>

<问题描述>

---

## 二、想法与点子

### 1. <一句话想法>

<展开，2–4 句，可选>

**建议去向**：知乎想法 / 文章选题 / 待验证的点子 / 留档

---

### 2. <一句话想法>

**建议去向**：……
```

**规则（提问区块）**：

- 一个问题一个编号，之间用 `---` 分隔，便于单独复制发布
- 标题**不加**序号以外的任何前缀（不写「问题一」「Q1」）
- **每个话题都必须有真标题。** 禁止 `合并描述`、`待定`、`T5 + T6` 这类占位标签冒充标题——合并或拆分后产生的新话题要重新给标题
- 描述里**不要**出现「以上是我的一些想法」这类收尾套话——它是要发出去的提问
- 每个提问下面**不要**附「为什么这么问」的说明（除非用户明确要）

**规则（想法区块）**：

- **用陈述句**，一句话能读完
- 「展开」是**可选的**——稿里本来只有一句，就不要硬扩写
- **建议去向**四选一，只写一个词，不加解释性长句：`知乎想法` / `文章选题` / `待验证的点子` / `留档`
- 详见 `references/ideas.md`

**两个区块都要遵守**：

- 交付后单独列一段**极简说明**：列出划分依据、合并了哪些、拆了哪些、**哪些归成了想法**。**这段不是发布内容**
- 如果有未核实的专有名词，另起一张 **`⚠️ 待确认` 表**，列出「稿里原文 / 疑点 / 需要你确认什么」
- **整份稿子没有可独立成立的提问时**，提问区块写「本稿没有可独立成立的提问」，**不要硬造**；想法照常交付

## 五、交付前自检

逐项回答「是/否 + 证据」：

1. **专有名词核对过**——人名 / 产品名 / 公司名 / 作品名 / 数字都核对了吗？改动的每一处都写明依据了吗？（见 `references/transcript-fidelity.md`）
2. **三类都分过了**——每一段都有归属吗？（提问 / 想法点子 / 未采用）
3. **没有丢掉想法**——**有没有哪一段填不出矛盾句式、但有明确主张，却被扔进了未采用清单？**
4. **一个矛盾**——每个提问是否只有一个核心矛盾？**最终描述**里有没有出现「另外」「还有一个问题」？
5. **填得出句式**——每个提问是否填得出「我看到 A，但应该是 B」？
6. **想法用陈述句**——有没有把疑问句放进想法区块？主语是想法本身，还是「我觉得」？
7. **具体对象**——标题里有没有具体的东西（产品名/作品名/场景）？还是全是抽象概念？
8. **念得出来**——把每段描述念一遍，像不像这个人真的会在知乎上这么问？
9. **第一人称还在**——有没有哪一段变成了第三人称的客观陈述？
10. **没替用户下结论**——有没有把「我怀疑」写成「事实是」？
11. **没替他补话**——每一句都能在原稿里找到依据吗？有没有我加的澄清、限定、免责？
12. **动机照原话**——动机句是照原话保留的，还是我改写/推测的？
13. **开放性**——有没有哪个提问其实已经把答案写好了，变成自问自答？
14. **没过度拆分**——每个问题都有具体场景支撑吗？有没有描述不足三句的？**有没有两问的回答者高度重叠、其实该合？**
15. **没过度合并**——有没有哪个提问其实装了两件事？
16. **每个话题都有标题**——有没有占位标签冒充标题？
17. **未采用清单说得通**——里面每一条都能说出**为什么连想法都不算**吗？
18. **能直接发**——单独把某一条复制出来，能直接贴进知乎提问框（或当一条想法发）吗？有没有残留「以下」「如上」这类依赖上下文的词？

任何一项失败，先改再交付。

## 七、本 skill 的更新方式

本 skill 自己也要从后续修改中学习，但**只提炼可迁移的通用规则，不把某一篇稿子的具体修改硬编码进来**。

1. **从具体反馈提炼通用规则**。用户说「这里太文绉绉」，**不能**更新成「不要用'信息差'这个词」；应该提炼成「读者是普通人时，抽象名词要换成他生活里的说法」。
2. **通过通用性测试**：换了主题还成立吗？能适用于口述稿、笔记、长文三种输入吗？能被明确执行吗？
3. **区分三类反馈**：通用规则 / 当前任务规则（这篇稿子要更讽刺）/ 局部修改（这一句换个说法）。只有第一类进长期规则。
4. **旧规则默认保留**，更新前建立清单，逐项确认保留 / 合并 / 改写 / 建议删除。**重写不等于重新发明。**
5. **优先合并，不无限膨胀**；每条规则必须对应一个真实失败模式。
6. **冲突不擅自决定**：方向相反、无法同时满足、要把"建议"升级为"必须"时，列出冲突交给用户。
7. **示例只用于解释规则，不反过来成为模板。** 本文件里的《凡人》、蓝牙耳机、蟑螂都是这一个用户的真实话题，**不是通用题材**。

**规则的优先级**：用户本次明确提出的新规则 > 本 skill 已有规则 > 上游来源。
