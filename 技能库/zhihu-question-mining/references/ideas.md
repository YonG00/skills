# 想法与点子：不是所有内容都要做成提问

> **定位**：本文件是 `SKILL.md` §1.2 与 §1.4 的配套方法，**本仓库原创**。
>
> **它解决什么**：本 skill 早期只认「一个核心矛盾」。于是稿子里**填不出那个句式的东西**——一个主张、一个观察、一个点子、一个方案——全部被归进「未采用清单」。**那是在丢东西。**
>
> 用户原话：「不仅要找问题，**不是问题，想法、点子这些也算，也需要提出来**」。

---

## 1. 三类内容，不是两类

| 类别 | 判据 | 产出 |
|---|---|---|
| **提问** | 填得出「我看到 A，但按理说 B」——**有落差** | 知乎提问（标题 + 描述） |
| **想法 / 点子** | 填不出落差，但填得出**一个主张、观察、设想或做法** | 想法条目（一句话 + 展开 + 去向） |
| **未采用** | 两者都填不出（纯背景 / 纯情绪 / 重复 / 转写噪声） | 未采用清单（附理由） |

**关键**：中间那一类是早期版本缺的。**「不是一个问题」不等于「没有价值」。**

---

## 2. 什么算「想法 / 点子」

五类都算，不必凑成疑问句：

| 类型 | 句式 | 例 |
|---|---|---|
| **主张** | 「我认为 X 应该……」「X 其实不是……」 | 「Agent 的成本优势只在某些环节成立，获客和履约是另外两笔账。」 |
| **观察** | 「我发现 X 和 Y 有关系」「越……反而越……」 | 「越是靠创造力的岗位，硬性打卡的副作用越明显。」 |
| **点子** | 「可以做一个 X」「如果能 X 就有用」 | 「做个工具，把评论区、客服记录和退货原因并起来看，判断下一步该卖什么。」 |
| **方案 / 做法** | 「如果要做 X，应该先……」「比较靠谱的顺序是……」 | 「想验证概率准不准，先在同一类任务上测，再换分布测第二次。」 |
| **标准 / 原则** | 「判断 X 的标准是……」「不该只看 X，要看 Y」 | 「判断一个 AI 助手好不好用，不该只看答得对不对，要看它在什么场景下能自己动。」 |

**共同点**：它**陈述**了什么，而不是**追问**什么。所以用**陈述句**提炼。

---

## 3. 什么仍然是「未采用」

别把这一条放宽成"什么都留着"：

- **纯背景信息**——介绍某人某事的来龙去脉，本人没有主张
- **纯情绪感慨**——只有情绪，没有主张（「这个事真的挺烦的」单独出现时）
- **转写重复**——同一句话说三遍，有效信息已在别处
- **别人的话且与本人无关**——引用了一段外部观点，但本人没有接话
- **没讲完就跳走的话题**——只有一个开头，看不出想说什么

判据：**问一句「这句话里有没有一个属于他的主张？」** 有 → 想法；没有 → 未采用。

---

## 4. 怎么提炼「一句话想法」

**要求**：

1. **用陈述句**，不用疑问句——疑问句是提问的地盘
2. **主语是想法本身**，不是「我觉得」——「我觉得 Agent 便宜」→「Agent 的成本优势只在某些环节成立」
3. **保留本人的措辞和具体名词**——不要把「获客、物流和退货」抽象成「履约成本结构」
4. **一句话能读完**；读不完说明里面有两件事 → 拆

**可以给 2–3 个候选**，标注取舍，推荐一个。跟标题一样，但**不追求反差和抓人**——想法是要**准确**，不是要**点击**。

---

## 5. 交付格式

**提问**和**想法**分两个区块，不要混在一起：

```
## 一、知乎提问

### 1. <标题>

<问题描述>

---

## 二、想法与点子

### 1. <一句话想法>

<展开，2–4 句，可选>

**建议去向**：知乎想法 / 文章选题 / 待验证的点子 / 留档
```

**「展开」是可选的**：稿子里如果本来就只有一句话，不要硬扩写成一段。

**「建议去向」四选一**，含义：

| 去向 | 用在什么情况 |
|---|---|
| **知乎想法** | 短、能独立成立、适合当一条动态发出去 |
| **文章选题** | 大到值得单独写一篇，但现在材料还不够 |
| **待验证的点子** | 需要做实验或查资料才能确认，先记下来 |
| **留档** | 有价值但暂时用不上，留着以后翻 |

**不要**给去向加解释性长句。一个词就够。

---

## 6. 同一段里既有提问又有想法

**分别提取，不要合并，也不要二选一。**

例：稿子里说「AI 助手现在都得掏手机打开 App，我觉得以后应该像打电话一样自然，但为什么现在做不到？」

- **提问**：「为什么 AI 对话框还不能像打电话一样用蓝牙耳机？」
- **想法**：「理想的 AI 交互应该像打电话一样自然，不需要掏手机。」

两者并存时**都提出来**，放在各自的区块里。

---

## 7. 自检

- [ ] 稿子里每一段都有归属吗？（提问 / 想法 / 未采用，**三选一**）
- [ ] **有没有哪一段填不出矛盾句式、但有明确主张，却被我扔进了未采用清单？**
- [ ] 想法用的是**陈述句**吗？（用了疑问句 → 它其实是提问）
- [ ] 想法的主语是**想法本身**，还是「我觉得」？
- [ ] 保留了本人的措辞和具体名词吗？有没有被抽象掉？
- [ ] 每句话想法的长度是一句话吗？超过一句是不是装了两件事？
- [ ] 未采用清单里的每一条，能说出**为什么连想法都不算**吗？
- [ ] 交付时两个区块分开了吗？有没有把想法混进提问里？

---

## 8. 边界情况

| 情况 | 处理 |
|---|---|
| 整份稿子都是想法，没有提问 | **照常交付**，提问区块写"本稿没有可独立成立的提问"。不要硬造提问 |
| 想法和某个提问说的是同一件事 | 可以都留——提问面向外部讨论，想法面向自己推进 |
| 想法太抽象，落不到具体 | 保留原话，标 `待具体化`，不要自己替它补具体 |
| 想法数量很多 | 按「具体程度 × 可执行性」排序；明显重复的合并 |
| 用户说"只要提问" | 只出提问区块，但**在未采用清单里保留想法的位置**，说明"这些是想法，本次未展开" |
| 想法里有事实错误 | 按 `transcript-fidelity.md` 先核对；不核实的标 `⚠️待确认`，不要因为它不是提问就降低核对标准 |
