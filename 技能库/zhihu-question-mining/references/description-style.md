# 问题描述：保住说话的那个人

> **来源**：规则提炼自一次真实的六轮修改记录。用户连续两次因为同一个原因退回——「要尽量贴合保留个人的语言风格」「不够接地气，感觉太文绉绉的」。
>
> **这是整个任务里最容易做坏的一步。** 口语稿转书面语时，绝大多数模型会不自觉地"整理"，结果读起来像专栏文章、像行业报告，就是不像一个真人在知乎上提问。

---

## 1. 要保留的六样

| 保留 | 具体表现 |
|---|---|
| **第一人称** | 「我发现」「我就在想」「我想要的其实很简单」 |
| **具体场景开头** | 时间、地点、动作：「我发现自己刚起床那半个小时…」 |
| **短句、一句一段** | 大量一句话成段，长短交替 |
| **口语连接词** | 我就在想 / 所以我更想问的是 / 就跟…一样 / 这个事我一直挺奇怪的 / 有时候觉得 |
| **具体名词** | 真实产品名（豆包、元宝、千问、DeepSeek）、作品名（《凡人》）、真实经历 |
| **情绪的痕迹** | 有点烦、挺奇怪的、我也想不通、折腾得比较头疼 |
| **困惑的开放性** | 可能 / 我也说不好 / 不知道是不是 / 这个我还没想明白 |

---

## 2. 只做三件事

1. **去重复**——同一句话说了三遍，留一遍
2. **理顺逻辑**——把来回跳的顺序摆正
3. **让别人能快速看懂你在问什么**

**就这三件。** 其余一切都属于"整理"，都属于过度加工。

---

## 3. 不要做的五件事

每一条都对应一次真实退回。

### 3.1 不要"整理"

- ❌ 加小标题、编号分点、提炼"核心观点"、加总结段
- ❌ 把散落的句子归并成"规范的段落"
- ❌ 给描述加开头交代（「近年来，随着…」）

### 3.2 不要拔高

| ✗ 拔高 | ✓ 原话 |
|---|---|
| 晨间认知功能激活滞后 | 脑子好像还没开机 |
| 决策链路调用效率低 | 就是不太容易马上想清楚 |
| 存在显著的交互摩擦 | 用起来还是这么麻烦 |

### 3.3 不要替用户下结论

用户说「我怀疑」，不要写成「事实证明」。用户说「我在考虑」，不要写成「我决定了」。

允许保留：**可能 / 我更倾向于 / 不知道是不是 / 目前看 / 我也说不好**。

### 3.4 不要写成预设答案

如果描述读起来像"我已经知道答案了，你来附和我"，真正懂的人不会来答。

**检查方法**：把描述里的判断句逐个标出来——它们应该是**提问的素材**，不是**提问的前提**。

### 3.5 不要用书面套语

进行、从而、基于、综上所述、值得注意的是、在一定程度上、由此、换言之。

### 3.6 不要替用户补充他**没说过**的说明

这是最容易漏掉的一条——它不像"拔高"那么明显，读起来甚至挺顺，但**那句话不是他说的**。

真实事故：某条描述里被加进了

> 「我并不是现在遇到了一个"该选什么专业"的问题。更多就是单纯好奇，」

用户回：「**没必要这么说明**」。原稿里从来没有这个澄清——是整理者**自己觉得**需要先撇清，于是替用户加了一句。

同类的还有：

| 被加进去的 | 问题 |
|---|---|
| 「（当然，这只是我个人的感受）」 | 用户没说 |
| 「我不是要批评谁」 | 用户没说 |
| 「我知道这个问题可能有点幼稚」 | 用户没说 |
| 「先说结论：……」 | 用户的口述里没有这个结构 |

**判断方法**：把这句话拿回原稿/原对话里找依据。

> **找得到 → 留；找不到 → 删。**

**为什么这条重要**：加进去的澄清会把**开放性问题变成防御性提问**。用户本来只是好奇，被加上一句"我不是遇到了问题"之后，读起来像在解释自己为什么问——这会削弱提问本身。

### 3.7 不要改写用户的**动机**

用户说的动机就是动机，不要替他换一个更"合理"的。

真实事故：

| 用户实际说的 | 被改写成 |
|---|---|
| 「就是好奇而已」 | 「我现在也不知道该从哪里进去」（T10） |
| 「想问的是有没有这种实验」 | （原稿的核心问题被换成了别的）（T2） |
| 「是分析打卡这件事」 | 「是不是公平问题」（T12） |

**处置**：动机句一律**照原话保留**。原话不清楚时**问用户**，不要用推测填上。

## 4. 完整 before / after（真实记录）

同一个话题（蓝牙耳机），同一个人的原始想法，两种处理。

### ✗ 一稿：整理感太重

> 现在手机打电话、微信语音或视频通话，都可以直接使用蓝牙耳机完成声音输入和输出。
>
> 但很多 AI 助手即使已经支持实时语音对话，实际使用时却很难做到类似"打电话"的体验：戴着蓝牙耳机，直接唤醒 AI，然后持续进行双向语音交流。
>
> 从技术上看，蓝牙耳机本身已经具备麦克风和音频输出能力，微信通话也能正常调用。
>
> 那么，为什么 AI 助手很难做到真正的"蓝牙耳机通话模式"？
>
> 这主要是手机系统权限、蓝牙协议、后台运行限制的问题，还是 AI 产品本身没有开放这类能力？

**问题在哪**：

| 症状 | 具体位置 |
|---|---|
| 书面语 | 「完成声音输入和输出」「具备麦克风和音频输出能力」 |
| 无具体对象 | 「AI 助手」——哪个？读者没有画面 |
| 段落长度均匀 | 每段都是 2–3 句，节奏像报告 |
| 没有个人感受 | 只有客观描述，看不出这个人为什么在意 |
| 术语 | 「双向语音交流」「蓝牙耳机通话模式」 |

### ✓ 定稿：接地气

> 这个问题我一直挺奇怪的。
>
> 现在正常打电话也好，微信语音也好，戴上蓝牙耳机，耳机既能听，也能直接说。
>
> 但像豆包、元宝、千问这些 AI，现在明明也都有语音对话了，为什么很多时候还是不能像打电话一样，直接戴着蓝牙耳机一直聊？
>
> 我想要的其实很简单。
>
> 比如我戴着耳机走路，直接叫一下 AI，然后问问题，它从耳机里面回答，我再接着问。
>
> 就跟打电话一样。
>
> 这个技术上应该也不是什么特别难的事情吧？
>
> 微信都能做到，为什么 AI 助手反而做不到？
>
> 到底是手机权限限制、蓝牙的问题，还是这些 AI App 本身没做？

**改了什么**：

| 动作 | 例 |
|---|---|
| 开头先给态度 | 「这个问题我一直挺奇怪的。」 |
| 换成人话 | 「完成声音输入和输出」→「耳机既能听，也能直接说」 |
| 具体产品名 | 「AI 助手」→「豆包、元宝、千问」 |
| 补个人场景 | 「我戴着耳机走路，直接叫一下 AI…」 |
| 加情绪 | 「就跟打电话一样。」「应该也不是什么特别难的事情吧？」 |
| 一句一段 | 9 段里 6 段是一句话 |
| 结尾仍留开放 | 「到底是手机权限限制、蓝牙的问题，还是这些 AI App 本身没做？」 |

## 5. 结尾格式

描述的最后，落到一个**明确的疑问句**（可加粗），后面可以跟 1–3 个追问：

```
所以我更想问的是：

**这种快速判断、快速解决问题的能力，到底能不能练？**

如果能练，平时应该怎么练？

还有就是，有没有什么比较实在的方法，可以让人早上更快进入状态？

不是那种"早睡早起、多运动"这种大家都知道的话。

而是比如做什么事情，确实能明显让脑子快一点清醒起来。
```

**注意最后两行**：先排除掉一个敷衍的答案（「不是那种…大家都知道的话」），再问真正想要的。这是口语提问里很自然、也很有效的一招。

---

## 6. 诊断「整理感」的三个方法

交付前把每段描述**念出来**，问三个问题：

1. **这个人会这么说话吗？** ——不会，就是书面化了
2. **有没有哪个词他根本不会用？** ——有，就换成他的说法
3. **段落长度是不是太均匀了？** ——是，就拆出一句一段的节奏

第三条特别容易被忽略：**整理感很大程度上来自段落长度的均匀**。真人说话是有长有短的。

## 7. 自检

- [ ] 第一人称还在吗？有没有哪段变成第三人称客观陈述？
- [ ] 开头是**具体场景**，还是「近年来…」式的交代？
- [ ] 有没有小标题、分点、总结段？（有 → 删）
- [ ] 段落长度是不是太整齐了？
- [ ] 有没有书面套语（进行 / 从而 / 基于 / 综上所述）？
- [ ] 抽象词有没有落回他生活里的说法？
- [ ] 具体名词保住了吗？（产品名、作品名、经历）
- [ ] 有没有把「我怀疑」写成「事实是」？
- [ ] 描述是不是读起来像**已经知道答案**了？
- [ ] **每一句都能在原稿/原对话里找到依据吗？** 有没有我替他加的澄清、限定、免责？
- [ ] **动机句是照原话保留的，还是我改写/推测的？**
- [ ] 单独复制这一条，能直接贴进知乎提问框吗？有没有「以上」「如上」这类依赖上下文的词？
