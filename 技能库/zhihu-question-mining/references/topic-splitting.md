# 从稿子到话题单元

> **定位**：本文件是 `SKILL.md` §1.1 的完整执行方法，**本仓库原创**。
>
> **它解决什么**：口语稿是**发散、重复、话题来回跳、没有小标题**的。直接按段落切会得到一堆没有矛盾的碎片，直接按主题切会把好几件事塞进一个问题。本文件给出从这种稿子里切出「一个提问 = 一个核心矛盾」的可执行过程。

---

## 1. 输入 / 输出契约

**输入**：一份口语稿（录音转写、随笔笔记、长文档——任何未经整理的连续文本）。

**输出**：四件东西，缺一不可。

1. **话题单元表**——每个单元一行，含 `id / 源位置 / 触发场景 / 稿中已有的疑问 / 核心矛盾 / 可用素材 / 处置`
2. **合并与拆分判定记录**——哪些合并了、哪些拆开了、依据是什么
3. **优先级排序**——按「具体程度 × 矛盾强度」，不按稿子顺序
4. **未采用清单**——稿子里哪些内容没进任何提问，以及理由

**三条硬约束**：

- **每个话题单元必须填得出「我看到 A，但实际是 B」**。填不出 → 它还不是一个提问。
- **每个单元必须有具体场景支撑**。没有 → 它是感慨或背景，不是提问。
- **稿子里的内容要么进某个提问，要么写进未采用清单**。不得静默丢弃。

---

## 2. 六步

### A. 标记

通读全篇，标出五类东西：

| 类别 | 是什么 | 用途 |
|---|---|---|
| **触发点** | 具体场景、不爽、疑惑的起点（时间、地点、动作） | **标题和描述开头的原料——最重要的一类** |
| **已有的疑问** | 稿子里已经带问号的句子 | 往往是话题单元的雏形 |
| **用户判断** | 他自己下的结论、给的解释 | 描述里保留，但**不能**写成提问的前提 |
| **事实与引用** | 外部信息、别人的话、数据 | 最多作为描述里的背景，**不构成话题** |
| **重复与岔路** | 说了几遍的、跑题的、没讲完的 | 重复的合并；岔路的进未采用清单 |

**不要在这一步切分**，先标完再切。

### B. 切单元

**切分信号**（满足其一就切）：

- **场景切换**：从「早上起床」跳到「AI 交互」——这是两件事
- **矛盾对象切换**：从「AI 的能力」转到「AI 的交互方式」——对象变了

**不切的反信号**：

- 同一矛盾的**举例、补充、换个说法再说一遍** → 不切
- 同一场景下的**不同侧面** → 不切
- 顺带提到的**背景信息** → 不切（它会成为描述的素材）

**合并规则**：稿子里分处两地但**共享同一个触发场景 + 同一个矛盾**的段落 → 合成一个单元。

> ⚠️ 口语稿的特征是**同一个想法会在不同时间点出现两次**。合并这一步的主要工作就是认出它们。

### C. 提炼核心矛盾

对每个单元，填空：

> **我看到 / 我遇到的是 ______，但按理说 / 大家都说应该是 ______。**

再补一句：**这两者的落差，卡在哪个环节？**

| 单元 | 矛盾 |
|---|---|
| 蓝牙耳机 | 微信打电话能直接用耳机双向说话，**但** AI 语音对话不行 |
| 《凡人》 | 组织追求「去个人化」，**但** 优秀作品又高度依赖具体的个人 |
| 早晨决策 | 我早上遇到新问题会懵，**但** 有些人遇到新问题就是能很快反应过来 |

**填不出这个句式的单元**，三种处置：

1. 它其实是**背景** → 并入邻近单元的「可用素材」
2. 它其实是**感慨**（只有情绪没有落差）→ 进未采用清单
3. 它其实是**两个矛盾混在一起** → 回到 B 拆开

### D. 定粒度

#### D.1 默认倾向：**存疑则合**

本任务要的是**能发出去的提问**，不是尽可能多的提问。所以粒度拿不准时，**合**而不是拆。

真实记录：某次初划分给出 **12 个话题**，用户在后续三轮里要求合并 **3 次**（T5+T6、T7+T8、T3+T12），**要求拆分 0 次**。最终收敛到 **9 个**。

**模型在这个任务上的系统性偏差是"拆得太细"**，不是"合得太粗"。调粒度时请先怀疑自己拆多了。

#### D.2 拆分的唯一正当理由：**答案体系不同**

两个话题要分开，必须能回答：**它们是不是需要不同的人、不同的知识背景来回答？**

| 成立（该拆） | 不成立（该合） |
|---|---|
| 「打卡制度怎么设计」vs「大脑能不能被复制」——医学/神经科学的人答不了管理制度 | 「30 岁做 AI 到 50 岁职业价值怎么变」vs「普通本科能不能走到 CTO」——**同一批职场人、同一套职业经验就能一起答** |
| 追问的目标对象完全变了 | 只是同一条职业/生活设想的**两个侧面** |

#### D.3 「另外」「还有一个问题」**不构成**拆分理由

> ⚠️ **这是真实误用，写下来避免重犯。**
>
> 上一版规则把「描述里出现『另外』『还有一个问题』」列为拆分信号。但模型把它**用到了原稿上**——理由是「原稿自己已经明确说『两个方面』『另外一方面』」，于是把 T5 拆成 T5+T6。用户随后要求合回去。
>
> **口语稿里的「另外」「还有一个问题」是说话人的口头连接词**，不是话题边界。一个人口述时，几乎每换一口气都会说「另外」。

判据修正：

- 这个信号**只看最终描述**，**不看原稿**——原稿里出现多少次都不算。
- 即使出现在描述里，也只是**提示**，仍要过 D.2 的「答案体系」测试。
- 更可靠的合并信号是：**两个话题的核心矛盾句式可以共用同一个主语和同一批回答者**。

#### D.4 两个方向的检测

**过度合并检测**（一个提问装了两件事）：

- **最终描述**里出现「另外」「还有一个问题」「顺便说」**且**两部分需要不同的人来回答 → 拆
- 描述里出现**两个互不相干的触发场景** → 拆

**过度拆分检测**（把一个提问切碎了）：

- 拆出来的问题**没有具体场景**支撑 → 合回去
- 描述**不足三句**、撑不起一个独立提问 → 合回去
- 两个问题**共享同一个触发场景** → 合回去
- **两问的回答者高度重叠**（同一批人、同一套经验） → 合回去
- 两个话题的**核心矛盾句式只差一个变量** → 合回去

#### D.5 合并/拆分之后必须重新给标题

**合并产生的新话题，必须补一个完整的标题。**

真实事故：合并 T5+T6 之后，产出里写成了 `**T5 + T6｜合并描述**`——**把占位标签当成了标题**。用户回：「T5 + T6，怎么没有标题？」

标题在阶段 2 已经定过，但那个标题只属于**合并前**的单个话题。合并后是一个新对象，必须重新给标题（可以复用其中一个，也可以重写）。

同理适用于**拆分**：拆出来的每一半都要有自己的标题。

#### D.6 一条元规则

> **如果用户已经认可了一套话题划分，不要继续往下拆。**
>
> 真实记录：用户说「不是，原来分出 7 点的文档挺好的，内容再润色就行」——此时改动范围**只剩标题和描述的文字**，重新划分话题属于越界。这是本任务最常见的一种过度执行。

### E. 排优先级

按 **具体程度 × 矛盾强度** 排序，**不按稿子顺序**：

| 维度 | 高 | 低 |
|---|---|---|
| **具体程度** | 有产品名/作品名/可复述的场景 | 全是抽象概念 |
| **矛盾强度** | 两边都成立、确实冲突 | 只是"我不太懂" |

稿子顺序没有意义——口语稿的顺序是想到哪说到哪。但**如果用户已经给出编号，就沿用他的编号**。

### F. 产出

按 §1 的契约输出四件东西。交付格式见 `SKILL.md` §四。

## 3. 判定测试

对每个候选单元跑四条：

| 测试 | 判据 | 不通过则 |
|---|---|---|
| **独立发布测试** | 单独把这一条复制进知乎提问框，读者不看其他条也能懂 | 有依赖上下文的表述，或本身是两个问题 → 改写或拆开 |
| **一句话矛盾测试** | 填得出「我看到 A，但实际是 B」 | 是背景或感慨 → 降级或进未采用 |
| **场景测试** | 有具体场景支撑（时间/地点/动作/对象） | 撑不起提问 → 合回邻近单元 |
| **不重复测试** | 与另一个单元不共享同一个触发场景 + 矛盾 | 合并 |

---

## 4. 自检

定稿前逐项回答，**给出「是/否 + 证据」**：

1. **稿里所有专有名词都核对过吗？**（人名 / 产品名 / 公司名 / 作品名 / 数字）——见 `transcript-fidelity.md`
2. 每个单元都填得出「我看到 A，但实际是 B」吗？
3. 每个单元都有具体场景支撑吗？
4. **每个拆分都有「答案体系不同」支撑吗？** 还是只因为原稿说了「另外」？
5. **有没有两个话题的回答者高度重叠、其实该合？**
6. 有没有哪个单元的描述里出现「另外」「还有一个问题」？（**只看最终描述，不看原稿**）
7. 有没有哪个单元描述不足三句？
8. 稿子里每一段都有归属吗？（进某个提问 / 进未采用清单）
9. **用户已经认可的划分，我有没有擅自改动？**
10. 稿子里重复出现的同一想法，有没有合并成一个单元？
11. **合并或拆分之后产生的新话题，都有标题吗？** 有没有「合并描述」这类占位标签？
12. 排序是按「具体程度 × 矛盾强度」，还是不小心按了稿子顺序？
13. 有没有把**外部信息**（别人的话、数据）误当成一个话题？

**数一下**：这次拆出的数量，比"最少能覆盖全部矛盾"多了几个？每多一个都要能说出 D.2 的理由。

---

## 5. 边界情况

| 情况 | 处理 |
|---|---|
| 稿子其实只有一件事 | **输出 1 个提问**，不要为了凑数硬拆。拆不出第三句描述的问题根本不是问题 |
| 稿子里大量外部信息 | 那些是**描述的素材**，不是话题。一个只有引用没有个人落差的段落 → 未采用清单 |
| 稿子是对某个已有知乎提问的回答 | 可以从中提炼**新的**提问，但**不要照抄原问题**；如果落差就来自原问题，如实说明「看到 X 问题下的讨论后想到」 |
| 用户已给出话题编号 | **沿用他的编号和划分**，只做文字润色 |
| 稿子里同一个想法出现三次 | 合并成一个单元；如果三次的措辞在演进，**取最后那次** |
| 稿子含敏感或可能违规的内容 | 提示用户，不擅自删改，也不帮忙规避审核 |
| 稿子极长（几万字） | 先按 A 步标记，再按「场景切换」粗切大块，逐块做 B–C，最后统一跑 D 定粒度 |
| 用户只要「简要提问」不要描述 | 只输出标题，但自检仍要跑「独立发布测试」 |
