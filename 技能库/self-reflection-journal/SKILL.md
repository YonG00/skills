# 自我思考成文

把零散表达整理成值得读、仍像作者本人写的文章。技能名沿用 `self-reflection-journal`；旧名 `zhihu-question-mining` 的平台提问结构不再适用。当前版本 2.1.0。

默认直接交付完整文章正文，不先交主题目录、观点清单或提纲。长稿按大的思考方向归并，通常约 2–4 篇；这是经验范围，不是数量指标。素材只够一篇就写一篇，同一方向优先合并，不为凑数量扩写，也不机械套用技术、行业、人生三分类。

## 保真与边界

- 保住说话的那个人：第一人称、真实场景、具体对象、数字、动机、个人措辞、比喻、情绪和犹豫。只做必要的去重复、理顺原有逻辑、让别人能看懂；不能把个人表达改成行业报告。
- 不替作者补充没说过的经历、动机、因果、论证、实验结果、行动计划或答案。每段都须能追溯到原稿；整理者新增联想默认不写入，用户要求扩展时单列“整理者补充”。
- 区分实际做过的实验、观察结果、当前判断、考虑中的方案与未解疑问。“可能”“我怀疑”“我觉得”不能改成定论；先支持、后来怀疑的变化要保留，不拼成一个始终成熟的观点。
- 情绪、普通日常、未完成的思考和相反判断都有记录价值，不以主张、核心矛盾或答案完整度筛选。但完整识别素材不等于每条都要塞进文章：与主线无关的枝节留在底稿，不能强行扩成独立文章。
- 存疑则合；“另外”“还有一个问题”、日期变化或新术语都不是拆篇依据。用户已认可的文章划分不再随意拆分。标题准确具体，不制造矛盾，不追求反差或流量。

## 工作方式

### 1. 读取与转写核对

以用户材料为依据；同时有录音时，用录音核对可疑处。只有录音时先用可用转写工具；不能处理就说明条件不足，不冒充听过。

核对专有名词、数字、否定词、说话人归属和会改变意思的断句。明显标点、无信息重复可修；不能确定的关键字保留并标“待确认”。外部检索只能提供名称候选，不能证明作者说的是那个词。未确认词不能成为后文论证前提；无关部分继续整理。详见 [转写保真](references/transcript-fidelity.md)。

### 2. 归并方向，找回思考的推进

工作底稿记录源位置、触发场景、问题、想法、经历、情绪、自我修正与发散，避免遗漏或编造；这些是内部分析维度，不是输出分类清单。

先问哪些材料在讲同一条探索，再跨段、跨日期归并。例如同一轮尝试里的训练、评测、复习和比赛反思，通常应串成一篇，而非各写一份技术笔记。篇内保留真实的判断先后：为什么这样想、遇到什么、哪里开始怀疑、又想到什么、什么仍没想清楚。不同性质的方向适当分开，避免在技术探索中突然塞入大段生活感慨；若作者明确把技术与人生选择联系起来，且联系本身是主线，则自然保留。

录音软件、转写方式、文件整理、手机电脑操作等通常属于素材记录过程；与本篇方向无关就不进入正文。只有作者深入讨论这些过程本身、且足够独立时，才考虑成文。不强求覆盖所有零散信息。详见 [方向归并](references/topic-splitting.md) 和 [想法与记录](references/ideas.md)。

### 3. 写成能独立阅读的文章

围绕素材已有的经历和疑问，自然推进，而非逐日记流水账。完整段落为主，长短自然交替；少量小标题辅助阅读，不能重新写成知识点清单。不固定套“背景—问题—分析—解决方案—总结”，也不规定每篇必须有相同环节。

保留“我就在想”“后来又觉得不对”等有思考含义的口语，删无意义空转。技术术语和个人比喻可以共存，不把“先打基础怪，再打精英怪”改成“构建分层能力体系”。允许自我否定、情绪、停顿和无明确结论，不硬补完美答案。标题不比正文更确定。详见 [行文风格](references/description-style.md) 和 [标题](references/title-craft.md)。

### 4. 交付与特殊请求

- 默认在对话里直接输出完整文章，每篇有真标题并能独立阅读，不依赖前面的分类说明。用户说“先看效果”时也直接给文章，不只给提纲或写作过程。
- 只有用户明确要求文件，才生成 Markdown、Word 或文件包。文章正文可以使用 Markdown 排版，不等于必须创建文件；Word 等格式按相应工具规范制作。
- 日期只用素材明确的信息，未提供时省略或标明整理日期，不虚构经历日期。只有用户明确要求研究、建议或代答时才扩展任务。
- 转写疑点、必要的编辑备注与实质删并说明放在正文之外，标为“整理备注（不属于发布正文）”。源位置对照保存在工作底稿，用户需要时再展示，不把编辑过程写进作者叙述。
- 用户明确要短记录、日记或逐步整理时遵循该请求；一句话素材可保留短条目，不强行成文。分阶段仅在用户要求时采用“核对与归并 → 文章初稿 → 润色”，不预设每步都要确认。
- 用户要博客版时调整标题、段落与已有背景，不能借机添论据或把个人猜测写成已证实事实。生成稿件不等于允许公开发布；上传或发布需明确授权，并遵守已约定的发布前确认流程。
- 私人原稿、录音、文章及来源底稿不提交到公开技能仓库。文件产物遵循所在工作区的资料目录约定；隐私细节给具体待处理项或可选匿名版，不自行改写真实经历。

用户说“直接整理”时一次完成。只有实质影响内容的歧义才询问，不因个别待确认词阻塞其他部分。

## 交付前检查

1. 是少量完整文章，还是按术语、日期或段落机械拆出的目录与笔记？篇数由材料决定了吗？
2. 技术与生活方向是否合理分开，原稿明确建立的重要联系是否保留？无关记录过程是否误入正文？
3. 每段有原稿依据吗？实验、结果、判断、方案、疑问是否混淆？重要情绪、未完成思考是否因“不像结论”被丢掉？
4. 是否保留第一人称、具体对象、动机、个人比喻、不确定性与观点演化？有没有补话或制造统一结论？
5. 念出来像作者自己分享吗？每篇能独立阅读吗？备注在正文之外，交付形式符合请求吗？

旧反馈仅继承保真经验；不恢复“纯情绪不采用”“必须有核心矛盾”“标题必须反差”“去掉我觉得”等已废除约束。历史与来源见 CHANGELOG、[来源索引](references/reference-registry.md) 及 [历史案例](references/worked-example.md)。
