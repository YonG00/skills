# 个人思考成文（self-reflection-journal）

将录音转写、随笔、对话和零散思考归并为少量完整文章，保留本人语言和思考过程。技能名不变；2.1.0 将默认目标从日志整理进一步调整为个人思考成文。原名 `zhihu-question-mining` 的平台提问任务已在 2.0 取消。

## 默认效果

长稿通常按大的思考方向归并成约 2–4 篇独立文章，这不是篇数指标：只够一篇就写一篇，同一方向优先合并，不按术语或日期拆成多份专题。技术探索与人生感慨适当分开；原稿明确建立的联系自然保留，不套固定分类。

每篇通过经历、困惑和判断变化自然推进。第一人称、真实数字、个人比喻、犹豫和情绪都可以保留；不写报告腔，不补实验结果或完美结论。与主线无关的录音、转写和文件操作不强塞进正文。

默认直接在对话里交付完整文章，不先交提纲、主题清单、Word 或文件包。只有用户要求文件时再生成；明确要求短记录、日记或分阶段时仍然支持。不会自动发布，不将私人素材提交到公开仓库。

## 使用

读取 [执行规范](SKILL.md)，或将整个目录安装到支持 SKILL.md 的技能目录。仓库源码更新不代表本机运行时副本已同步。

> 把这段转写整理成几篇真正能读的个人文章。同一条探索尽量归并，保留我本人的口语、经历和前后判断变化，不替我下结论，直接给正文。

关键转写歧义标待确认；只有录音时先使用可用工具转写，不能冒充听校。未完成片段有记录价值，不为篇幅补写。

## 演进

| 版本 | 默认目标 | 继续保留或调整 |
|---|---|---|
| 1.x | 平台提问与想法条目 | 继承保真、不补话、差异不大则合并；不恢复核心矛盾和反差标题要求 |
| 2.0 | 按主题组织的个人日志 | 保留情绪与未完成思考，取消平台格式；仍容易按日期记录、拆成主题文档 |
| 2.1 | 按方向组织的少量完整文章 | 强化口语、思路演化与信息取舍，技术和人生合理分篇，不凑数量 |
