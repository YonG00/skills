# 自我思考日志（self-reflection-journal）

把自我思考的录音、转写稿、随笔和对话整理成个人日志，供回看、继续思考或后续博客发布。原技能名为 `zhihu-question-mining`，2.0起取消平台提问定位。

## 能整理什么

- 问题：还在困惑什么、哪里没想通。
- 想法：当前判断、观察、点子和设想。
- 记录：发生的事情、当时状态和情绪，即使没有结论。
- 发散：从一个念头想到另一个念头，或者暂时没讲完的线索。

这些内容可在同一节里自然共存，不强制四类清单，不强求每条有核心矛盾或可执行方案。默认形成第一人称 Markdown 日志，有需要再调整为博客版；不会自动发布。

## 使用

把整个目录安装到支持 SKILL.md 的技能目录，或在当前仓库中直接读取 [执行规范](SKILL.md)。

示例请求：

> 把这段录音整理成我的思考日志，保留我问的问题、想到的点子和中间的发散。没想明白的地方也留下，不用替我下结论。

已有文字时直接处理；只有录音时先用可用工具转写。关键识别歧义要标待确认，不能凭空编造听写或用户动机。

默认一次完成。用户要求先看划分、逐步确认时，再分阶段推进。

## 与旧版的区别

| 旧版 | 当前 |
|---|---|
| 标题＋问题描述，面向平台提问 | 一份按主题组织的个人日志 |
| 核心矛盾与反差标题 | 真实经历、想法和未解问题 |
| 纯情绪和没讲完的内容可能不采用 | 有个人记录价值就保留 |
| 想法必须去掉“我觉得” | 保留第一人称和不确定程度 |
| 固定阶段确认、疑问句收尾 | 按用户节奏，不强制结论和结尾格式 |

## 文件

- `SKILL.md`：执行规范。
- `references/`：转写保真、主题整理、想法记录、标题与行文方法。
- `references/worked-example.md`：明确标注的历史案例，不是当前模板。
- `CHANGELOG.md`：2.0改动与1.x历史记录。
- [聊天模式提示词](../../prompts/self-reflection-journal.md)：无技能加载能力时使用。

用户原稿、录音和实际日志留在用户指定的资料目录，不随技能公开。许可沿用 LICENSE。
