# 真实案例：一次六轮修改的完整记录

下文的文件章节号与表格引用属于 1.x 当时的版本，可在 Git 历史中追溯，不代表现行参考文件仍保留这些章节。2.1 的匿名验收情景见本文第 7 节。

> **来源**：一次真实的知乎提问整理会话。用户给出一份口述稿，要求整理成可发布的知乎提问，前后共 **6 轮**反馈、**3 个版本**。
>
> **本文件是过程记录，不是模板。** 案例里的《凡人》、蟑螂、起床状态都是**这一个用户的具体话题**，不具约束力。规则本身见 `SKILL.md` 与其余 references。
>
> **⚠️ 摘录政策**：原始产出含约 4,100 字符的个人生活内容。本文件**只保留必要摘录**（标题、反馈原话、以及一段对照），**不收录全部问题描述全文**——把一个人的生活细节完整放进公开仓库，超出了「提炼规则」所需。若需要全文存档，应放在私有位置。

---

## 1. 案例概况

| | |
|---|---|
| **输入** | 一份口述转写稿（约 37 行，多个话题混在一起，无小标题） |
| **任务** | 整理成可发布到知乎的提问：简要的提问 + 问题描述 |
| **输出** | 7 个相对独立的话题 |
| **往返** | 6 轮反馈，3 个版本 |
| **结局** | 第 7 版的标题与描述被用户接受 |

**关键**：用户的反馈**从头到尾只针对两件事**——标题够不够抓人，描述够不够像他本人说话。话题划分本身第一版就对了。

---

## 2. 六轮修改年表

### 轮 1｜需求

> 「理解文档内容，我要准备发表到知乎提问里面。每个话题，帮我整理，简要的提问（要符合内容，精准有力），还有问题的描述。」

改稿者的处理原则（第一版就定对了）：

> 「按'一个知乎问题 = 一个核心矛盾'的方式整理，尽量把口语里的重复、发散收紧，同时保留你真正想讨论的冲突点和开放性。」

**产出**：7 个话题，标题偏书面，描述偏"整理"。改稿者自评：

> 「这版比较适合直接发布：问题本身清楚，但没有把自己的观点写成预设答案，这样更容易吸引真正懂这个领域的人回答。」

→ 提炼：**不写成预设答案**（FM-7）

---

### 轮 2｜描述要保留个人语言风格

> 「问题描述内容，要尽量贴合保留个人的语言风格」

改稿者的自诊断：

> 「上一版确实有点'整理得太标准'，把你原本那种一边想、一边追问、一边举例的个人感削弱了。这版我会尽量保留你的表达方式：第一人称、真实困惑、带一点自己的判断和例子；主要只做三件事——**去重复、理顺逻辑、让别人能快速看懂你到底在问什么**。」

→ 提炼：**只做三件事**（`description-style.md` §2）、**保留六样**（§1）

---

### 轮 3｜两个标题被抓出来

> 「4. AI 到底怎样才能真正融入日常生活…有一点奇怪，
> 5. 为什么很多作品一旦失去'灵魂人物'，整个味道就变了？**应该提到《凡人》这个作品吧，问题提问不够尖锐，不够吸引关注**」

改稿者的诊断：

> 「第 4 个**太泛，像行业报告题目**；第 7 个**抽象层级提得太早**，把《凡人》这个最能吸引人点进去的具体对象藏掉了。建议把标题先从'具体痛点/具体作品'切进去，再在描述里把问题上升到更大的讨论。」

→ 提炼：**FM-2 标题太泛**、**FM-3 具体对象被藏**，以及「标题给具体，描述做升华」的顺序

---

### 轮 4｜越界：把问题合并成了"大问题"

> 「你是不是忘了，我要的是，准备发表到知乎提问里面，**拆分多个问题**」

改稿者承认：

> 「刚刚我把第 4、7 两块又写成了'一篇大问题'，确实偏离了你的目标。你要的是把录音里的想法**拆成多个可以单独发布的知乎提问**，每个问题只抓一个矛盾点，配一段贴近你原本说话方式的问题描述，而不是把所有思考塞进一个问题里。」

→ 提炼：**FM-4 把多个矛盾塞成一个"大问题"**

---

### 轮 5｜反方向的越界：拆过头了

> 「不是，**原来分出 7 点的文档挺好的，内容再润色就行**」

→ 提炼：**FM-5 过度拆分**，以及那条元规则——

> **用户已经认可的话题划分，不要继续往下拆。改动范围只剩标题和描述的文字。**

---

### 轮 6｜最终问题：不够接地气

> 「问题还是不行，**不够接地气，感觉太文绉绉的**」

改稿者的最终诊断（这一条把整个失败机制说透了）：

> 「上一版虽然保留了你的逻辑，但还是'**整理感**'太重，像专栏文章，不像普通人真的会在知乎上这么问。
>
> 你原文其实有一个很明显的特点：**不是先想好一个大道理再提问，而是从生活里一个具体的不爽、一个疑惑开始，越想越觉得这个事有问题。** 这个味道应该保留。」

→ 提炼：**FM-1 整理感太重**、**FM-6 抹掉个人语言风格**

## 3. 三版标题演进

7 个话题的完整三版对照表在 `references/title-craft.md` §2（含每个话题的「一稿 / 三稿 / 定稿」）。

**最典型的一例**：

```
一稿：为什么 AI 助手不能像微信电话一样通过蓝牙耳机直接对话？
三稿：为什么 AI 助手不能像微信电话一样直接用蓝牙耳机对话？
定稿：为什么微信打电话能直接用蓝牙耳机，AI 对话反而不行？
```

**改法**：把「AI 为什么不能做到 X」改成「**X 能做到，AI 反而不行**」——同样的信息，加了反差。

## 4. 最终交付的七个标题（仅标题）

1. 为什么微信打电话能直接用蓝牙耳机，AI 对话反而不行？
2. 人的决策能力能练出来吗？为什么我刚起床的时候特别难做决定？
3. 想法太多、什么都想研究，是好事还是在浪费精力？
4. AI 都这么厉害了，为什么平时用起来还是这么麻烦？
5. 有想法到底该不该说出来？会不会说多了反而把自己的东西都送人了？
6. 蟑螂到底怎么弄最有效？难道人类到现在还没一套靠谱办法吗？
7. 《凡人》这么大的 IP，怎么换几个人以后，味道就能差这么多？

**共同特征**：都有**具体对象**（蓝牙耳机 / 起床 / 《凡人》）、都有**反差或张力**、都用**口语**、都**只有一个问号或一问一追问**。

## 6. 如果要用这份记录做回归测试

拿一份**口述稿**跑一遍，检查：

- [ ] 拆出的话题数与原稿的**矛盾数**匹配（不是段落数）
- [ ] 每个标题里都有**具体对象**
- [ ] 描述念出来**像人话**（段落长度不均匀）
- [ ] 没有出现小标题、分点、总结段
- [ ] 没有把两个矛盾塞进一个提问
- [ ] 单独复制任意一条都能直接发布

> **注意**：本案例的输入稿不在本仓库（含个人内容）。回归测试需要另找一份口述稿，或使用用户提供的材料。


## 7. 2.1 匿名验收情景（现行规则）

下列材料为人工构造，不使用私人原稿。用现行 SKILL 实际成文后检查，不以“包含关键词”代替语言与保真验收。

| 情景 | 输入要点 | 验收观察 |
|---|---|---|
| 长篇混合材料 | 多次训练和评测探索、机器人规划设想、职业与生活感慨交错 | 同一训练主线归并，方向各自独立；通常少量文章，不按每个术语拆文，篇数不硬凑 |
| 文章语言 | “有点打击”“先把基础怪打了”“我就在想”与技术术语共存 | 保留具体口语、比喻和疑问，正文为自然段落，不变成研究报告 |
| 判断变化 | 起初觉得单一误差够用，执行失败后开始怀疑 | 交代前后变化，不能声称新评测方案已被证明有效 |
| 信息取舍 | 同时记录手机录音、文件改名和对失败的感受 | 无关操作不进正文；感受与主线有关时保留，不能当“无结论”删除 |
| 保真与短稿 | “我只试过两次，还不知道是否稳定”；另一稿只有一句感慨 | 不新增成功率或下一步计划；短稿只写短记录，不为数量扩写 |

检查时保留输入、输出与逐项判据到本地资料目录，不把真实作者素材加入公开仓库。这些情景是验证方法，不是每篇文章都必须遵守的内容结构。
