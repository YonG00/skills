# 按大的思考方向归并成文

先理解全稿，再决定哪些思考能够共同撑起一篇文章。默认交付文章，不把以下内部归并过程当成最终输出。

1. 在底稿按源位置识别场景、疑问、经历、判断、情绪、发散、自我修正和中断点。素材完整识别，不等于全部进入正文。
2. 跨段、跨日期寻找同一条思考主线。同一轮探索中的做法、失败、评测、复习和新的设想，优先写成一篇；术语数量、换日期、“另外”“还有”都不决定篇数。
3. 用原稿已有联系串起变化：最初为什么想做、遇到什么、发现哪里不合理、又想尝试什么、什么还没想清楚。若时间明确，保留先后；不能确定时不编日期，也不把旧看法说成最终定论。
4. 技术探索与人生感慨通常分开，避免无关内容突然闯入。但作者若在讨论“为什么还想留在这个技术方向”，技术与职业的联系可能正是主线，不能机械隔离。
5. 存疑则合。同方向优先归并，只有两部分各有独立主线、放在一起会反复跳题时才拆。长稿约 2–4 篇是经验范围，非数量指标；不凑篇数、不扩写薄弱材料，也不把领域例子变成固定分类。
6. 不相关的录音软件、转写方式、文件整理、设备操作、上传过程通常不进文章。仅当这些过程本身被深入思考且有独立内容时，才考虑另成一篇。
7. 已获认可的文章划分不再随意拆分。发生用户授权的归并调整后，重新检查标题范围，不用“T1+T2”占位标签。

底稿可记录 `源位置 / 内容与确定程度 / 所属方向 / 去向`。去向包括正文、并入哪篇、暂存未完片段、与主线无关留底稿、重复噪声。实质删改或有争议的取舍在正文外说明，不必为每个语气词写删除清单。

归并后的检查：任意一篇能否独立阅读？同一实验经历是否被拆成多份笔记？不同日期的怀疑与修正有没有被抹平？是否为了全覆盖而夹入无关过程？若用户明确要日记或短条，则遵循该请求，不强改成文章。
