# 保住思考的那个人

只做必要的三件事：去重复、理顺原有逻辑、让别人能看懂。保留第一人称、真实场景、具体对象、数字、动机、个人措辞、比喻、情绪和疑问。

“我就在想”“后来又觉得不对”“这确实有点打击”能表达思考过程，不是都要删的口头噪声。删无意义空转，不删语气中的犹豫与自我修正。技术文章也应像本人分享，不因涉及专业术语就改成研究报告。

例如“得先把基础怪打了，才能打精英怪”，不必改成“构建分层渐进式能力培养体系”；“我原本以为不会这么差”不应抽象成“泛化效率存在挑战”。这些是风格示例，不能给没有这些话的原稿补上比喻或情绪。

每段都问：原稿里找得到依据吗？不能增加作者没表达的经历、动机、论证、因果、实验结果、答案或计划。作者说“是不是批量太小了”，只能保留疑问，不能写成“增大批量有效提高泛化”。区分实际做过、观察到、当前判断、考虑中的方案与未解问题。“我在考虑”不能变成“我决定了”。

以完整段落为主，长短自然交替，少量小标题帮助读者跟上思路；不把每句话变成条目，不统一套用“背景—问题—分析—解决方案—总结”。一篇文章可以有感慨、有否定、有相反判断，结尾也可以没有答案。不强制总结、升华、行动清单或疑问句收尾。

跨日期的认识变化要讲清前后，不拼成作者一开始就知道的成熟结论。与主线无关的素材制作过程不进正文；待确认词和编辑说明放在正文之外。念一遍：像这个人自己会说的话吗？有哪些报告腔？顺畅是否来自补造的逻辑？
