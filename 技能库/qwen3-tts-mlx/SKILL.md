# 口播稿与本地纯人声配音

按用户认可的音色生成知识分享配音，保持标准普通话、清晰咬字、自然有精神的表达。略快但不赶，不刻意夸张；不加入背景音乐，尽量去掉参考录音中的环境声。原始稿件、录音、音色档案、模型和作品都留在本地资料目录，不进入公开 Git。

## 先主动请求许可

用户仅给稿件，不代表授权加工或合成。开始前主动说明：拟进行口播整理、使用哪份音色、是否沿用纯人声与语速，以及产物位置，询问是否开始。可以一次询问整条流程。

- 只同意整理稿件：先交口播稿，合成前再请求许可。
- 已明确授权整理并生成：在该范围内连续完成，不重复索要同一许可。
- 已指定成稿并明确要求合成：视为本次合成授权，不强制先问一次才能执行。
- 更换音色、增加云端上传、制作视频或公开发布：不从配音许可推断授权，先主动询问。

## 1. 处理口播稿

保留作者的第一人称、经历、数据限定和思考变化。公式只讲目的与核心直觉，不逐个读变量、求和、上下标；表格只提关键对比与结论，不逐行念。具体公式、表格和参数另存画面参考，不删除其依据。不把猜测改成实验结论。

主标题、任务代码名、网址和编辑备注不直接送入 TTS。补短过渡；专业名词首次出现可用中文解释。缩写或同音词读不好时，用经用户认可的中文读法，记录变更。用户已确认的口播稿不再擅自重写。细节见 [口播整理](references/speech-prep.md)。

交付口播 Markdown、仅包含应读内容的 TXT、画面参考。公式与画面提示不混进配音。用户只要口播整理时，到此结束。

## 2. 读取已保存音色

通过 `--profile`、`QWEN_TTS_PROFILE` 或运行时 `local_config.json` 找本地 profile；在技能仓库中也可读取 `资料/音色库/默认音色.json`。当前约定的默认档案 ID 为 `knowledge-male-clean-v1`，它来自用户认可的净化参考人声。音色不是固化在模型权重里的“新说话人”：需保留参考 WAV、逐字稿、配置及哈希。

缺少档案时询问用户，不换成通用声音，不重新猜一段参考。不得把参考 WAV、声纹、私人逐字稿或模型强制加入 Git。档案结构和迁移见 [运行与音色档案](references/runtime.md)。

## 3. 本地合成

先 `prepare` 生成计划和实际读法预览，再在用户已授权当前稿件与音色后，以计划摘要运行 `synthesize`。

```bash
python scripts/narrate.py prepare --text 口播.txt --profile 本地profile.json --out 项目目录
python scripts/narrate.py synthesize --plan 项目目录/plan.json --approved-sha256 已获准的摘要
# 同一计划、同一参考才能断点续跑
python scripts/narrate.py synthesize --plan 项目目录/plan.json --approved-sha256 已获准的摘要 --resume
```

目录按工作区约定使用 `资料/YYYY-MM-DD_HHMMSS_主题/`（Asia/Shanghai）。依赖复用已验证的隔离 Python 环境。生成前检查模型、参考与依赖是否就绪；未经授权，不把私人文稿发给官方演示或其他云服务。网络仅用于必要的模型/依赖下载时，先说明体积，不能声称“完全离线”却上传参考。

短稿尽量整段连续生成。长稿按完整句和自然段组成约 200–300 字的语意段，保持相同参考和参数，逐段生成、净化、核对，失败只重试当前段。合成不同片段不得自动更换参考音色。写入状态与音频哈希，恢复时复用已核对片段。

Qwen3-TTS Base 的 `speed` 参数目前不直接实现语速；脚本用保留音高的实际速度处理。Base 克隆不支持情绪指令控制，不能声称传一条“更激情”指令就生效。CustomVoice 与 Base 是不同权重；0.6B CustomVoice 有预置音色，但不具备 1.7B 的指令风格控制。当前默认语速系数约 1.08，可按用户反馈调整。

## 4. 纯人声与检查

使用经用户认可的净化参考；长稿每段应用相同降噪方案，再用固定增益统一人声响度，避免动态拉高停顿里的底噪。段落间留短停顿与边缘淡入淡出，不加背景音乐。DeepFilterNet 可降噪，但不保证去除所有音乐、混响，也不能凭处理参数宣称“录音棚品质”。

逐段回转写检查漏读、异常重复和截断；疑似混入参考末字时，定位正文起点后再裁剪，不能凭猜测盲裁。数字、否定词和专业术语重点人工复核。自动转写相似度只是检查工具，不等于发音标准认证或完整听评。保留 QA 记录；失败不得标完成。

导出 `voice.wav`（原生24kHz、单声道、24bit PCM）、`voice.mp3`、原口播稿、实际读法、`segments.json` 和状态。不要通过上采样冒称提高原生音质；合成声音标为 AI 合成，不冒充本人录制。

## 5. 交接 motion-video

输出 `motion_handoff.md`，说明无配乐人声文件、总时长、稿件、画面参考与段落时间。`segments.json` 只是段落时间，不是逐字时间；后续 motion-video 仍需按自己的流程建立逐字对齐。

用户计划用于 B 站知识分享，可建议 16:9，但不能直接开始渲染、添加音乐或投稿。取得下一阶段授权后再使用 `motion-video-workflow`，沿用人声，不无故重合成或重混音。仓库源码与运行时安装副本分别核验，未同步不得声称已安装新版。
