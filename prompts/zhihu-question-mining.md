# 聊天模式提示词：知乎提问挖掘

> **对应 skill**：`zhihu-question-mining`
>
> **用法**：把口述稿 / 转写稿粘进聊天，然后贴出下面任意一个方案。适用于两种输入：
> ① 聊天里已经有一段对话，要从中提炼；② 直接粘一份稿子。
>
> **执行方式**：分 **4 个阶段**，一次只做一个。每个阶段结束停下并打印 `⏸ 阶段 N 完成`；你检查没问题就说「继续」。
>

## 方案 A：联网可读链接（推荐）

适用：聊天模式**能访问网页**。规范从 GitHub 现读，永远最新；提示词本身只管阶段编排。

```
先完整读取这三份规范，读完再按它们处理**上面的内容**：

1. https://raw.githubusercontent.com/YonG00/skills/main/zhihu-question-mining/SKILL.md
2. https://raw.githubusercontent.com/YonG00/skills/main/zhihu-question-mining/references/topic-splitting.md
3. https://raw.githubusercontent.com/YonG00/skills/main/zhihu-question-mining/references/description-style.md

读完不要复述规范内容。按下面的【分阶段契约】执行。

════ 分阶段契约（最高优先级）════
整件事分 4 个阶段，一次只做一个。

· 每次回复的**第一行**必须是：`【阶段 N/4：名称】`
· 每次回复的**最后一行**必须是：`⏸ 阶段 N 完成，等你说「继续」`
  打印后立即停止，不得开始下一阶段、不得提前写后面的内容。
· 我说「继续」→ 下一阶段。我说「跳过」→ 跳过。我说「回到阶段 N」→ 回退重做。
· 我指出问题时，只改那个问题，改完重新打印本阶段完成行；**不要顺手重写别的**。
· **一次回复跨越两个阶段 = 错误**：立刻停止，只保留当前阶段的内容。

阶段 1｜转写核对 + 话题划分
  先做转写核对，再出话题单元表 + 每个单元的核心矛盾 + 合并/拆分说明。
  **不要写标题，不要写描述。**

  **① 转写核对（不能跳）**
  口述稿是语音转写的，专有名词可能听错。一个听错的词会孕育出一整个假话题。
  · 通读时对每个专有名词（人名 / 产品名 / 公司名 / 作品名 / 数字 / 专业术语）
    问一句：**这个词在这个句子里合不合理？**
  · 不要只判断"这词存不存在"，要判断"**这词在这句里合不合理**"——
    真词错词最危险（例：稿里写 DeepMind，但语境指向 DeepSeek，两个都是真公司）
  · **能联网就先搜**核对「名称 + 语境」；**搜不到 / 多个候选 / 语境对不上 → 直接问我**，不要猜
  · 改动的每一处，用一张表写明「稿里原文 → 核对结果 → 依据」
  · **不得**把未核实的词当话题的事实基础

  **② 话题划分**
  · 每个单元必须填得出：「我看到 ______，但按理说 ______。」
    填不出 → 它只是背景或感慨，说明理由后放进未采用清单。
  · 每个单元必须有具体场景支撑。
  · 稿子里每一段都要有归属（进某个单元 / 进未采用清单）。
  · **默认存疑则合。** 我要的是能发出去的提问，不是尽可能多的提问。
    拆分的唯一正当理由：**两个话题需要不同的人、不同的知识背景来回答**。
  · **「另外」「还有一个问题」不构成拆分理由**——口语稿里这是口头连接词，
    几乎每换一口气都会说。这个信号**只看最终描述，不看原稿**。
  · 检查两个方向：有没有一个单元装了两件事（**最终描述**里出现「另外」「还有一个问题」
    且两部分需要不同的人回答）？有没有拆得太碎（缺场景、描述不足三句、
    与邻项共享同一矛盾、**两问的回答者高度重叠**）？
  · **如果我已经给过话题编号或说过某个划分可以，就沿用，不要再拆。**

阶段 2｜标题
  为每个话题给 3–5 个候选标题，逐个标注淘汰原因，最后推荐一个并说明理由。
  · **具体对象优先**：产品名、作品名、真实场景，比抽象概念抓人。
  · **加反差**：「A 能，B 为什么不能」「都这么厉害了，为什么还这么麻烦」。
  · **动词和人话**：「蟑螂到底怎么弄最有效」而不是「如何系统治理蟑螂」。
  · **允许一点情绪**，但不夸张、不虚假悬念、不蹭无关热点。
  · 不用书面套语：浅析 / 探析 / 成因 / 初探 / 系统 / 转化。
  · 一行以内，问号最多一个。
  · **不要把所有候选都堆给我选**——给一个推荐 + 一句理由。

阶段 3｜描述
  按我确认的标题，为每个话题写问题描述。
  · **第一人称**，从**具体场景**开始（时间、地点、动作）。
  · **短句，一句一段**，长短交替。段落长度不要均匀。
  · 保留**口语连接词**（我就在想 / 所以我更想问的是 / 就跟…一样）和**具体名词**。
  · 保留情绪的痕迹（有点烦、挺奇怪的、我也想不通）。
  · **只做三件事**：去重复、理顺逻辑、让别人能快速看懂你在问什么。
  · **不要**：加小标题、分点、提炼"核心观点"、加总结段、拔高措辞、用书面套语。
  · **不要**替用户下结论（「我怀疑」不许写成「事实是」）。
  · **不要写成预设答案**——困惑要保留开放性。
  · **不要替我补充我没说过的说明**：不加澄清、限定、免责
    （例：不要加"我并不是遇到了什么问题，只是好奇"）。
    判断方法：这句话在原稿里找得到依据吗？**找不到就删。**
  · **不要改写我的动机**：我说"就是好奇"，就写好奇，不要换成别的。
  · 结尾落到一个明确的疑问句（可加粗），后面可以跟 1–3 个追问。
  · **如果我让你合并两个话题：合并后必须给一个新标题**，
    不要写「T5 + T6｜合并描述」这类占位标签。

阶段 4｜交付与自检
  · 输出完整可发布版：编号 + 标题 + 描述，条目之间用 --- 分隔，便于单条复制。
  · **每个话题都必须有真标题**——检查有没有 `合并描述`、`待定`、`T5 + T6` 这类占位标签。
  · 如果有未核实的专有名词，另起一张 **⚠️ 待确认表**。
  · 然后单独列一段**极简说明**（话题划分依据、合并了哪些、拆了哪些）——
    明确标注这段**不是发布内容**。
  · 最后跑自检，逐项给「是/否 + 证据」：
    专有名词核对过 / 一个矛盾 / 填得出句式 / 标题有具体对象 / 念出来像人话 /
    第一人称还在 / 没替我下结论 / 没替我补话 / 动机照原话 / 保留开放性 /
    没过度拆分 / 没过度合并 / 每个话题都有标题 / 单条能直接发。
  · 任何一项失败，先改再给我。

现在开始阶段 1。
```

· ✗「AI 到底怎样才能真正融入日常生活，而不是有问题时才拿手机出来问？」→ 太泛，像行业报告题目

· ❌ **不要替我补充我没说过的说明**：不加澄清、限定、免责

## 四个阶段对应什么

| 阶段 | 交付物 | 你检查什么 |
|---|---|---|
| 1 转写核对 + 话题划分 | 核对表 + 单元表 + 核心矛盾 + 合并/拆分说明 | **① 专有名词对不对**（听错的词会孕育出假话题）；**② 划分够不够粗**——默认存疑则合 |
| 2 标题 | 每话题 3–5 候选 + 推荐 | 有没有具体对象、有没有反差、像不像人话 |
| 3 描述 | 问题描述 | **像不像你本人在说话**；有没有小标题/分点/拔高；有没有替你多说一句 |
| 4 交付 | 可发布全文 + 说明 + 自检 | 单条能不能直接复制发布；每个话题都有标题吗 |

**为什么闸门设在阶段 1**：这是**唯一一处一旦错了、后面全要重做**的地方。

- **专有名词错** → 整个话题建在假对象上（实例：ZEV 实为 Jev、DeepMind 实为 DeepSeek）
- **粒度错** → 真实记录：初划分 12 个话题，用户三轮要求合并 3 次、要求拆分 0 次，最终 9 个

而**划分一旦被认可就不许再动**（用户原话：「原来分出 7 点的文档挺好的，内容再润色就行」）。先确认划分，后面才不会反复。

## 用法要点

| | |
|---|---|
| **怎么推进** | 阶段末尾会打印 `⏸ 阶段 N 完成`。检查没问题 → 说「继续」 |
| **发现问题** | 直接说改什么，**不要自己动手改**；它会改完重新打印完成行 |
| **已经有话题划分** | 直接说「话题划分我认可了，从阶段 2 开始」 |
| **只要标题** | 说「跳过阶段 3」 |

**发现它越界时**（一次做两个阶段、或阶段 1 就写标题）：

```
停。越界了。只保留【阶段 N】的内容，删掉后面阶段的，重新打印完成行。
```

**发现它偷偷重新划分了话题**：

```
话题划分不要动。只改标题和描述的文字。
```

## 已知漂移与纠偏

| 漂移现象 | 一句话纠偏 |
|---|---|
| 一次做多个阶段 | 「停，越界了，只保留阶段 N」 |
| 阶段 1 就开始写标题和描述 | 「阶段 1 只给转写核对 + 话题划分」 |
| **专有名词没核对就往下写** | 「先核对稿里所有专有名词。搜不到的问我，不要猜」 |
| **基于一个可疑的词建了话题** | 「这个词你核实了吗？没核实就先问我」 |
| **原稿里出现「另外」就拆** | 「口语里的『另外』不是话题边界。只有两个话题需要不同的人回答才拆」 |
| 重新划分了已认可的话题 | 「话题划分不要动，只改文字」 |
| **合并后没给标题** | 「合并后是新话题，要重新给标题。不要写『T5 + T6｜合并描述』」 |
| **替我加了没说过的话** | 「这句我在原稿里没说过，删掉」 |
| **改写了我的动机** | 「动机照我的原话，不要换」 |
| 描述里出现小标题 / 分点 / 总结 | 「去掉小标题和分点，改成连续的口语段落」 |
| 描述变得文绉绉 | 「念出来像不像我本人在问？抽象词换成人话」 |
| 标题太泛 / 像报告 | 「从具体对象切进去，加反差」 |
| 把两个矛盾塞进一个提问 | 「这个提问装了两件事，拆开」 |
| 拆得太碎 | 「这几条其实是一个话题，合回去」 |
| 忘了打印阶段标记 | 「每轮第一行标阶段，最后一行打印完成行」 |
