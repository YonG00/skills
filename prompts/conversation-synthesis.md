# 聊天模式提示词：Conversation Synthesis

> **用法**：在**一段已经聊完的对话末尾**贴出下面任意一个方案，让模型把这段对话整理成文章。模型手里已经有整段对话，**不需要再粘贴一遍**。
>
> **为什么需要这个文件**：`SKILL.md` 是给**能读文件**的 Agent 用的；聊天模式读不到 `references/*.md`，所以必须内联或转成 URL。
>
> **⚠️ 同步义务**：本文件是 `SKILL.md` 的**派生副本**。改完 skill 后按文末 [同步清单](#与-skillmd-的同步清单) 检查这里是否过期。**提示词过期不会报错，只会让模型悄悄按旧规则走。**

---

## 方案 A：联网可读链接（推荐）

适用：聊天模式**能访问网页**。规范从 GitHub 现读，永远是最新版。省 token，也不会过期。

```
先完整读取这两份规范，读完再按它们处理**上面这段对话**：

1. https://raw.githubusercontent.com/YonG00/skills/main/conversation-synthesis/SKILL.md
2. https://raw.githubusercontent.com/YonG00/skills/main/conversation-synthesis/references/conversation-to-outline.md

读完后按下面的【停止契约】执行。不要复述规范内容。
```

> 读完之后，再把方案 B 里【停止契约】之后的段落接上即可——或者直接把方案 B 整段发出去（它是自包含的）。

## 方案 B：自包含（不能联网时用）

```
以上是我们完整的对话。现在把它整理成一篇有观点的文章——不是复述聊天记录，
也不是把资料排版整齐。

════ 停止契约（最高优先级）════
· 这一轮你只允许输出「问题链 + 判断变化点 + 文章骨架表 + 信息资产归属表」，
  一篇正文都不许写。
· 最后一行原样打印：
  ⏸ 骨架完成，等你说「开始写」
· 我确认骨架后，你再写正文。
· 如果你这一轮写了正文 = 错误：立刻停止，删掉正文，只保留骨架。

════ 如果这段对话写不成文章，直接说 ════
先把判断变化点找出来：哪些地方推翻了之前的判断？写成
  原判断 → 触发物 → 新判断
· 找到 ≥1 个 → 继续。
· 找到 0 个 → 明确告诉我「这段对话目前只是收集了资料，不构成文章」，
  并说明缺什么。**不要硬凑一篇看起来完整的探索文章。**

════ 上下文可能不全，不许编 ════
如果早期对话已经不在你的上下文里，**直接说**，不要凭印象补细节。
凭记忆编出来的用户原话，比缺一段更糟。

════ 骨架怎么做（七步）════
1 **论元**：把对话切成最小的主张单元，每个标类型与状态。
  类型：事实 / 用户判断 / 推演 / 假设 / 问题 / 证据 / 反例 / 未解决
  状态：现行 / 已被我修正 / 已废弃
  ⚠️ 我后来改过说法的地方，旧表述一律标「已被修正」，正文只能用最新版。
  ⚠️ 你自己产生的推演不许标成「用户判断」。
2 **问题链**：把「问题」类论元连成　Q0 → … → 当前问题，标出每个问题是被什么回答的。
  两个问题之间如果没有回答连接，说明链是断的——要么漏了论元，要么这段对话没推进。
3 **判断变化点**：就是上面那个三元组。这是文章真正的骨架节点。
4 **章节**：一节 = 一次判断变化 + 支撑它的证据。逐节能说清：
  「原来以为 X，因为 Y，现在认为 Z」。一节里含两次独立变化 → 拆开。
  删掉某节后中心问题仍成立 → 它不属于主线。
5 **中心问题**：在 1–4 之后才写这句话。答案应该比最初的问题**更准或更窄**；
  如果和最初一样，说明对话没推进。
6 **资产归属**：把每个论元、以及搜到的每项资料（数据/法律/论文/案例/工具/
  网站/渠道/关键词）各归一处：
  某节正文 / 核心证据 / 重要补充 / 反例限制 / 后续资源 / 边缘 / 已废弃
  **总数必须守恒**——任何一项没有归属都要写明理由。
  允许的理由只有：不相关 / 重复 / 来源差 / 已过时 / 有更好的来源 / 我不要。
  **「删了以后文章更顺」不是理由。**
7 **骨架表**，就这六列：
  | 节 | 这一节回答什么 | 判断变化（原→现） | 支撑证据 | 源位置 | 这一节不写什么 |

════ 信息很多时先问我 ════
如果资料很多，先给我三层清单（核心信息 / 有价值资源 / 边缘信息），
让我决定：保留 / 删除 / 放正文 / 只留链接 / 放附录。别自己定。
只有我说「直接写、不用问我」，才按这个优先级办：
推动问题变化的信息 > 支撑核心判断的资料 > 可继续使用的工具/渠道 > 一般背景。

──────── 以下是写正文时才执行的，现在先不用管 ────────

════ 不替我说话 ════
· 不能把「我怀疑」写成「事实证明」，不能把「我在考虑」写成「我决定了」。
· 你自己的观点不许塞进我的第一人称。
· 不确定就保留：可能 / 我更倾向于 / 至少说明 / 现有证据支持 / 目前还不能证明。
· 保留具体：时间、地点、动作、当时想到什么、后来什么变了。
  不要把具体经历润色成空泛的"高级表达"。
· 我的个人经历是**问题入口**，不是社会统计——不能从「我经历过」跳到「大家都这样」。

════ 证据 ════
· 可核验内容（数字 / 法律 / 政策 / 研究 / 国外制度 / 机构定义）第一次出现就给来源。
· 来源优先级：法律原文·政府文件·官方统计 > 原始论文 > 权威国际组织 >
  研究机构 > 可靠媒体 > 行业媒体 > 社区/个人经验。
  社区只用来证明「有人这样讨论」，不承担核心事实。
· **相关 ≠ 因果。** 证据不够就降级表达。特别检查这些词：
  导致 / 造成 / 证明 / 必然 / 就是因为。
· 观点不需要假装成文献——我的经历、价值判断、明确标注的推演，不用硬挂链接。
· 链接放在第一次出现的地方，不要全堆到最后的"参考资料"。

════ 推进思考（写完初稿后，对核心判断再过一遍）════
· 依据是什么？所以呢？真正想说什么？（只能写"很重要"就是没想透）
· 什么情况下这个判断不成立？
· 是不是二元对立？有没有中间态？
· 系统在奖励什么、惩罚什么？这是机制解释，还是已被证明的因果？
· 纸面平等 ≠ 实际可用：谁掌握信息、谁承担举证、谁有专业人员、谁耗得起
· 这个方案会制造什么新问题？——**副作用检查**：隐私 / 监控 / 形式主义 / 数据造假 /
  合规成本 / 权力滥用 / 新的不平等
· 建议要落到机制：谁负责、数据从哪来、多久一次、谁能看、异常怎么办

════ 结构 ════
· 先内部想 ≥5 个候选标题，选一个同时含：**讨论对象 + 核心矛盾 + 信息增量**。
· 小标题必须独立可读。✗「真正的问题」「另一种可能」 ✓「为什么 X 会产生 Y？」
· 章节跟着**问题变化**走，不按资料分类（✗ 数据 / 法律 / 国外案例 / 论文）。
· 新概念从问题里长出来，不要突然塞一堆术语。

════ 风格 ════
· 长文用**连续 prose**。多个短语能写成一句话，就不要拆成大量单独行。
· **禁止「标签行 + 内容行」**：
  ✗ 如果： / A > 0 / 那么： / 增加： / P(y|x)
  ✓ 当 A > 0 时提高 P(y|x)，当 A < 0 时降低 P(y|x)。
· 列表只用于步骤/清单/对比/选项/分类，不用来制造节奏或强调。
· 控制金句密度：不要每段都像海报。避免过量粗体、单句成段、极短反问、排比、
  「不是 X，而是 Y」。默认节奏：事实 → 解释 → 推理 → 判断 → 必要时强调。
· 接地气靠**具体**（有人、有动作、有成本、有后果），不靠"说白了/本质上/其实就是"。
· 少用：本质上 / 真正 / 核心 / 值得关注 / 重新定义 / 范式 / 赋能 / 从某种意义上。
· **AI 感不是某个词，而是所有段落都被加工得过于整齐**（每段三点、每节都总结）。
· **锐利** = 找到真正起作用的变量：不是停在「机会没人发现」，而是追问
  「还是根本没人买？」
· **有洞见** = 把原本分开的信息连起来，让**问题本身发生变化**——不是写一句漂亮金句。
· 反讽只能建立在事实矛盾上，不许为了尖锐去猜别人动机。
· 犀利 ≠ 武断：有证据就直接，没证据就留边界，不要为气势提高因果强度。
· 直接说：`问题在于……`，不要`在进一步对这一问题进行分析以后，我们可以发现……`

════ 结尾 ════
· 不是重复摘要。至少回答：最初在问什么？哪个判断被修正？现在最可信的是什么？
  还不知道什么？下一步该验证什么？
· 如果开头用了具体场景，可以回环，但要用全文的新理解**重新解释**它，不能原样重复。
· 最后一段要真的结束。✗「这个问题值得进一步思考。」

════ 交付前七项审计，逐项给结论 ════
1 **证据** — 重要数字/法律/政策/研究都有来源？相关没被写成因果？
2 **用户真实性** — 有没有替我表态？有没有把旧措辞写回来？
3 **对话完整性** — 重要资源、渠道、案例、链接有没有莫名消失？
4 **结构** — 只读标题能看懂路线？每节为什么在这？有没有可以删掉而不影响文章的章节？
5 **文章形态** — 有没有一词一行 / 不必要列表 / PPT 感 / 金句过密？
  有没有"听着很对、其实没信息"的空话？
6 **逻辑强度** — 事实/判断/推演混了吗？找过反例和中间态吗？
  **换成技术、职业、学习、研究等其他领域，这套逻辑还成立吗？**
7 **结尾** — 问题升级了吗？收住了吗？

任何一项失败，先改，再把正文给我。
```

## 用法要点

| | |
|---|---|
| **贴在哪** | 对话**末尾**。模型手里已经有整段对话，不要再粘一遍 |
| **两阶段** | 骨架 → 你确认 → 正文。**不要**让它一次成文 |
| **骨架就是验收点** | 骨架表里的「判断变化」列如果是空的或牵强的，说明这段对话还不该写成文章——这时候停，比写出来再改省事得多 |
| **资产归属表是保险** | 它保证辛苦搜来的东西不会在成稿时悄悄消失 |

**发现它越界时**（直接写正文、或骨架里没有判断变化却继续），回一句：

```
停。越界了。只保留骨架（问题链 + 判断变化点 + 骨架表 + 资产归属表），删掉正文。
```

**如果它说「这段对话写不成文章」**——那是正确行为，不是失败。说明这段对话目前只是在收集资料。可以让它告诉你缺什么，再决定是继续聊还是写成一份**资料整理**（那是另一种交付物，不是探索文章）。

## 已知漂移与纠偏

| 漂移现象 | 一句话纠偏 |
|---|---|
| 直接写正文，不给骨架 | 「停，先只给骨架」 |
| 骨架没有「判断变化」列或内容是空的 | 「判断变化点重新找：原判断 → 触发物 → 新判断」 |
| 把我的假设写成事实 | 「这条标成推演，不要当事实」 |
| 用了我后来纠正过的旧说法 | 「用我最新那次的表述」 |
| 出现一词一行 / 标签行 + 内容行 | 「排版检查：标签和内容同行，短句凑一行」 |
| 每段都金句、大量加粗 | 「金句密度过高，压回正常长文节奏」 |
| 搜到的资料不见了 | 「资产归属表里这几项去哪了？补回来或说明理由」 |
| 结尾是"值得进一步思考" | 「结尾做问题升级，不要机械总结」 |

| 若 skill 改了 | 则本文件要改 |

| 七阶段任一步骤或字段 | 方案 B 的【骨架怎么做】 |
