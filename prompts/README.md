# 聊天模式提示词

给**没有文件系统**（可能也没有联网）的纯聊天模型用的提示词。

| 文件 | 对应 skill | 用法 | 阶段 |
|---|---|---|---|
| [`technical-course-private-tutor.md`](technical-course-private-tutor.md) | `technical-course-private-tutor` | **开课时**贴出，然后按「继续 / 下一节」逐节推进 | 一次一节 |
| [`conversation-synthesis.md`](conversation-synthesis.md) | `conversation-synthesis` | **一段对话聊完之后**，在末尾贴出，让它把这段对话整理成文章 | 7 阶段 |
| [`self-reflection-journal.md`](self-reflection-journal.md) | `self-reflection-journal` | 从个人口述和稿子整理问题、想法、记录与发散，形成日志 | 默认一次完成，按需分阶段 |

## 提示词的推进方式

| 提示词 | 阶段 |
|---|---|
| 讲师 | 一次一节（走完路线图为止） |
| 对话合成 | 1 骨架 → 2 初稿 → 3 论证加固 → 4 语言与风格 → 5 证据与链接 → 6 结尾 → 7 标题与成稿 |
| 自我思考日志 | 默认一次整理；用户要求时按核对与归并 → 日志初稿 → 博客润色推进 |

**闸门都设在最容易做错的那一步**：讲师是「一节讲完就停」，对话合成是「骨架确认后才写正文」，自我思考日志则按用户要求决定是否分阶段，不强制每步确认。

## 为什么需要单独一份

`SKILL.md` 依赖文件系统读取 `references/*.md`。聊天模式读不到文件，所以必须：

1. **内联**（方案 B：规则全部写进提示词），或
2. **转成 URL**（方案 A：让模型现读 raw 链接，永远是最新版，更省 token）

## 提示词都是派生副本

它们是各自 `SKILL.md` 的**压缩重述**，不是独立规范。**改了 skill 必须同步这里**——提示词过期不会报任何错，只会让模型悄悄按旧规则走。

同步方法：每份提示词末尾都有「与 SKILL.md 的同步清单」和机检关键词。

## 分阶段提示词的设计

| 机制 | 作用 |
|---|---|
| **停止契约** | 用机械的终止行（`⏹` / `⏸`）代替"讲完就停"这种模糊要求。带显式终止符的指令，遵循率明显高于不带 |
| **分阶段交付** | 讲师：一次一节；对话合成：先骨架后正文。**用消息边界当硬闸门**，比单条提示词里写"不要多写"有效得多 |
| **越界纠正话术** | 发现它多写了，直接回一句固定的话，不用重发整个提示词 |
| **漂移纠偏表** | 列出常见漂移与一句话纠正话术 |

## 通用注意

1. **`raw.githubusercontent.com` 有 5 分钟 CDN 缓存**。改完 skill 立刻去聊天里测，模型可能读到旧规则。等 5 分钟或换新会话。
2. **别点「继续生成」**。出现那个按钮说明模型想写更多，点了等于批准它越界。
3. **方案 A 需要模型确实能联网**。如果它说读不到链接，改用方案 B。
