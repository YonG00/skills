## [1.0.0] — 本地合并版

**变更类型**：以 v3 为主线重组为可执行规范，并补上 v3 缺失的执行方法与静默丢失的规则。

### 合并方式

1. **以 v3 为骨架**（它是唯一完整自洽的一版，19 部分 / 59 条）。
2. **基础版作为存档与核对基线**：全文保留在 `references/base-version.md`，逐条映射到 v3。
3. **v3 的细节规则按主题抽到 `references/`**，`SKILL.md` 只保留可执行主干、硬约束与检查项。
4. 比对中发现的静默丢失**予以恢复并标注来源**（本节末尾）。

### 本仓库原创

| 新增 | 位置 | 说明 |
|---|---|---|
| **对话 → 文章骨架的七阶段方法** | `references/conversation-to-outline.md` | v3 第 13 条只给了"问题链"的**形状**，没给推导过程；第 10 / 20 条反复要求"信息资产不能无缘无故丢"，却没给核对机制。本文件补上：论元抽取（含"用户后续修正覆盖先前表述"的状态机制）→ 问题链重建 → **判断变化点识别** → 章节切分 → 资产归属与**守恒核对** → 中心问题定稿 → 骨架表 |
| **「判断变化点为 0 时不得成文」的停止条件** | 同上 Stage C | 上游只说文章应"让问题更准"，没说什么时候**不该写** |
| **骨架表第六列「这一节不写什么」** | 同上 Stage G | 把"不进入本节的信息资产"写在计划里，防写作阶段资料倒灌 |
| **骨架表 + 信息资产归属表** | 同上 | 把 v3 的"不能丢"变成可审计的总数守恒 |

### ★ 基础版 → v3 的静默丢失（本仓库恢复）

逐条比对 17 条基础版规则后，**整条完全缺失的：无**；但查出 **4 处局部静默丢失**。按 `references/skill-maintenance.md` 第十四部分「旧规则 = 保留……即使准备删除，也不应直接删除，应先标记『建议删除：原因……』交给用户决定」，本仓库**先恢复并标注**，同时列为待人工确认。

| # | 丢失内容 | 核实依据 | 恢复位置 |
|---|---|---|---|
| **1** | **基础版第 5 条的"用户筛选权"**：原文允许用户决定「保留 / 删除 / 放正文 / 只留链接 / 放附录」。v3 改成模型内部自行分级，默认工作流也不经过用户 | v3 第 21/22 条只有"先回收再筛选"与优先级分级，无用户决策权 | `SKILL.md` §三 |
| **2** | **基础版第 10 条的"删除必须有理由"清单**：不相关 / 重复 / 来源差 / 已过时 / 有更好的来源 / 用户不要；以及**「不能只是因为『删了以后文章更顺』」** | **实测**：v3 全文不含「删除必须有理由」「已过时」「更顺」；这三点只在基础版出现 | `references/conversation-to-outline.md` Stage E |
| **3** | **基础版第 12 条的两项风格要求**：「锐利」（找到真正起作用的变量）、「有洞见」（把分开的信息连起来、让问题发生变化）；以及接地气的差/好对照例 | v3 只保留"接地气"独立条目（第 43 条），"犀利"并入第 45 条；**实测 v3 全文「锐利」0 次，「洞见」仅 1 次且出现在第 31 条中间态语境**，与风格要求无关 | `SKILL.md` §七 + `references/structure-and-style.md` |
| **4** | **基础版第 17 条压缩时丢掉的三项终检**：信息资产（重要资源/渠道/案例/链接有没有莫名消失）、空话（听着很对其实没信息的句子）、通用性（换成技术/职业/学习/研究仍成立吗） | v3 第十一部分审计由 9 项缩为 6 项（54–59）。**实测**：v3 全文无「空话」；「信息资产」只在第四部分与第十八部分出现，**不在终检**；「通用性」只在第一部分第 2 条，**针对的是 Skill 规则而非文章** | `SKILL.md` §十 + `references/quality-audit.md` |

> 第 4 项特别值得注意：**「空话」和「信息资产」对应的是两个真实且独立的失败模式**（说正确的废话、搜索白做），v3 的六项审计确实没有覆盖。而「通用性」与第 2 条同名但对象不同——第 2 条管 Skill 规则该不该永久保留，这一项管文章结论能不能迁移，两者不可互相替代。
