# Reference Registry

Skill 的外部知识地图。**Skill 保存"如何思考"，Registry 保存"去哪里重新找到证据和原始知识"。**

## 字段定义

| 字段 | 含义 |
|---|---|
| `title` | 来源名称 |
| `url` / `位置` | 原始出处 |
| `type` | blog / paper / docs / github / case |
| `topic` | 涉及主题 |
| `purpose` | 为什么保存 |
| `supports` | 支持哪些规则或判断 |
| `retrieved_at` | 最近访问时间 |
| `notes` | 简短说明 |

## 本 skill 的来源性质

**本 skill 没有博客文章作为上游。** 它的规则全部提炼自**一次真实的六轮修改会话**——用户给出口述稿，要求整理成知乎提问，前后被退回 5 次。

这与仓库里另外两个 skill 不同（它们的上游是博客园的公开文章）。因此这里需要记录的主要是**案例来源**，而不是文档链接。

**摘录政策**：原始产出含约 4,100 字符的个人生活内容。仓库中只保留**必要摘录**（标题、反馈原话、一段对照），不收录全部问题描述。理由与边界见 `worked-example.md` 开头的摘录政策说明。

**不公开的部分**：

- 用户原始口述稿（未提供，不在本仓库）
- 7 个话题的完整问题描述全文
- 会话中出现的其它个人信息

## 维护约定

1. **不要把具体话题写进规则。** 《凡人》、蟑螂、蓝牙耳机都是这一个用户的题材，规则里出现它们只能是**举例**，不能变成判据。
2. 若原始案例被用户补充或更新，先更新 `worked-example.md` 的年表，再检查规则是否要跟着改。
3. 涉及知乎平台规则的内容（折叠、限流、标题党判定）**会变**，使用前必须重新核实，不能依赖本仓库的旧描述。
