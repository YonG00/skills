# 技术课程私人导师（Technical Course Private Tutor）

一个用于**逐节精读技术课程材料**的 Agent Skill。

它把 lecture notes、讲义 PDF、视频转录稿、GitHub chapter book、论文配套课程材料，重建成**一条可以一节一节走完的连续知识路径**——而不是一份读完就忘的摘要。

> 本仓库对应 `SKILL.md`（执行形态）与 `README.md`（可阅读的形态）。二者来自同一套知识体系：**Skill 是可执行的方法，Blog 是可阅读的方法。**

---

## 它解决什么问题

把一份技术讲义丢给通用模型，最常见的失败不是"讲错"，而是**讲得不像在教人**：

| 失败模式 | 表现 |
|---|---|
| **拆节不会拆** | 按原文小标题或视频时间戳切节，于是"该合并的被平铺、该重排的照抄顺序"；甚至只在口头上说"要按认知依赖切分"，却给不出推导过程 |
| **节名是名词不是问题** | 路线图写成「FLAN：早期 Instruction Tuning」——这是主题，不是学生要解决的认知任务 |
| **边界没有定义** | 路线图只有"这节讲什么"，没有"这节不做什么"，于是写正文时一路铺开 |
| **拆节对了，但太紧凑** | 路线图完全合规，可单节把 3 个教学拍点压进连续几段，读起来像"高密度讲义"而不是授课。根因通常更隐蔽：核心问题里用「而」并列了两个疑问，表面是一句话，实际是两个认知任务 |
| 用术语代替理解 | 「模型表现可以分成 capability 和 behavior 两层」——但学生还没看出这两者有什么区别 |
| 抢跑 | 第 3 节就开始解释第 22 节的 DPO loss，因为"顺便说一下会更完整" |
| 一节塞多个任务 | 学生读完只记得"讲了很多东西"，说不出到底多懂了哪一件 |
| 板书腔 | 普通因果关系被拆成 `long SFT data ↓ longer responses ↓ higher preference` |
| 目录推动 | 按"定义 → 数学形式 → 优点 → 缺点 → Benchmark → 延伸"展开，而不是按学生此刻真正产生的问题展开 |
| 为了完整而继续 | 核心已经讲清楚，却继续加例子、加类比、加 benchmark |
| 无来源的发明者 | 凭印象写"某某在 20XX 年提出"，年份或作者是错的，形成更难纠正的记忆 |
| 越更新越臃肿 | Skill 变成堆满一次性案例和固定答案的仓库，而不是越来越会判断 |

本 skill 的每一条规则都对应上面某一种可重复出现的失败模式——这是它的准入标准，不是装饰。

## 核心主张

### 1. 先会拆节，才谈得上教学

这是本版最重要的能力，也是最容易被含糊过去的一步。给定一份材料，必须能**推导**出路线图，而不是宣称"拆成 15–30 节"。

七阶段：**清单化 → 问题链 → 合并/拆分判定 → 依赖排序 → 旁支分流 → 粒度校准 → 产出**。

配套四条判定测试（合并 / 拆分 / 删除 / 原子性）、一张必须填满六列的路线图、一份覆盖核对表（原子单元总数守恒）、一份承诺点清单。完整方法见 [`references/section-splitting.md`](references/section-splitting.md)。

**唯一的硬性要求**：每节的核心问题必须是**疑问句**，且「本节不做什么」不能为空——边界没定义就不许开工。

### 2. 三条元原则

```
课程材料决定主线   →  认知依赖决定顺序   →  当前小节决定边界
```

> **路线图负责让学生知道未来会学什么；当前正文负责让学生只学现在该学的东西。**

### 3. 一节 = 一个认知问题，而不是一个主题

写正文前必须先能说出：**「这一节其实就是：________。」**
如果说不清，说明这一节仍然包含多个教学任务，应继续拆分。

### 4. 先看见区别，再给概念

`具体冲突 / 两个例子 → 学生看出差别 → 给这个差别命名 → 解释为什么 → 回到课程材料`

概念名称应该帮助学生**压缩已经形成的理解**，而不是代替理解本身。

### 5. 新技术第一次出现时，给一个"历史锚点"

用 1–3 句话回答：**什么时候出现的？谁提出/发布？当时为什么需要它？**

目标是给概念加一个长期记忆挂钩：`概念 + 时间 + 人/机构 + 当时的问题`。学完整门课后，学生脑中应自然浮现一条粗略技术线，而不是一串互不相干的方法名。

但历史锚点必须**服务当前认知问题**——如果它开始喧宾夺主，就应该停止。

### 6. 每节以固定的四件套结束，然后停下

一句话总结（压回最朴素的说法）+ 进度 + **一个**理解检查（不给答案）+ 克制的下一节预告（1–2 句，只提问题）。

### 7. 用户可以从任何一节开始

说「从第七节开始讲」就进第七节，只补理解该节所需的最小前置（标注「补充前置：」），不整节重讲，也不修改路线图本身。

```

├── SKILL.md                          # 可执行规范（主文件）
```

## 安装 / 使用

作为一个 Agent Skill 使用：把 `technical-course-private-tutor/` 整个目录放进你的 skills 目录即可（`SKILL.md` 带有 `name` / `description` frontmatter）。

作为提示词使用：直接读取并遵循 `SKILL.md`。

典型触发方式：

```
带我逐节学这份讲义：<链接 / 文件>
```

它应该先给你一份**主干路线图**（每节一个疑问句 + 本节不做什么），然后只讲第 1 节。之后按 `继续 / 下一节 / 往下` 推进；也可以直接说「从第七节开始讲」。

## 更新本 skill

按 [`references/skill-maintenance.md`](references/skill-maintenance.md) 的工作流：

```
收集反馈 → 区分局部/任务/通用 → 跨主题通用性测试 → 建立旧规则清单
→ 优先扩展或合并 → 检查旧规则是否丢失 → 冲突交给用户决定
→ 更新 SKILL.md → 更新 CHANGELOG.md → 新来源写入 reference-registry.md
```

三条硬约束：

1. **每条规则必须对应一个失败模式**——不为"看起来更完整"添加规则。
2. **旧规则默认保留**——重写不等于重新发明。
3. **新旧规则冲突不擅自决定**——列出冲突点，交给用户裁决。

## 还有哪些没有解决

- **拆节质量仍依赖模型的阅读能力**。方法给出了流程与判定测试，但没有自动化的"拆得对不对"校验：覆盖核对表与自检清单目前仍是**模型自检**，不是可执行测试。
- **历史锚点的事实核实依赖联网能力**。没有联网时只能执行 `SKILL.md` §3.5 的保守策略（明确说"不确定"），不能凭记忆补年份和作者。
- **理解检查的难度校准**没有客观标准，目前依赖 §5.3 的定性要求与"优先挑边界情形/反例"的出题法。
- **整学期级材料的分组规则较粗**：先按"讲"分组、每讲独立跑七阶段，讲与讲之间的依赖只记"前置讲"，未定义跨讲的全局重排。
