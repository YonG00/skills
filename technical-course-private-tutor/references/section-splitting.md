# 拆节：从材料到主干路线图

> **定位**：这是 `SKILL.md` §1.2 的完整执行方法。`SKILL.md` 只保留契约与摘要，本文件保留完整流程、判定测试、失败目录与 worked example。
>
> **它解决什么**：上游规范只说「按认知依赖而非原始时间戳机械切分」，但没有给出**怎么做**。结果是技能只能声明"要拆成 15–30 节"，无法真的推导出这些节。本文件补的就是这个推导过程。

---

## 1. 输入 / 输出契约

**输入**：一份完整材料（lecture notes / PDF / 视频转录稿 / GitHub chapter / 教材章节）。

**输出**：四件东西，缺一不可。

1. **原子单元清单**（Stage A 的产物，内部工件，不必全部展示给学生）
2. **主干路线图**——表格，六列：
   `节 | 核心问题（一句话） | 源位置 | 前置节 | 主要难点 | 本节不做什么`
3. **覆盖核对表**——每个原子单元 id → 归属（某个节 / 某个旁支桶）
4. **承诺点清单**——本节先不给解释、留到第 N 节兑付的清单

**硬约束**：

- 每节的核心问题必须是**疑问句**，不是名词短语。
- 每节的「本节不做什么」不能为空。**边界没定义就不许开工。**
- 覆盖核对表中，单元总数必须守恒：`Σ(各节归属) + Σ(各旁支桶归属) = 原子单元总数`。

---

## 2. 七阶段

### A. 清单化

全篇通读一遍，切成**原子单元**。每个单元记录：

| 字段 | 含义 |
|---|---|
| `id` | 单元编号 |
| `源位置` | 页码 / 时间戳 / 标题（用于后续忠实度核对） |
| `对象` | 它引入了什么（概念 / 公式 / 算法 / 数据集 / 实验 / 系统） |
| `它回答的问题` | 写成疑问句 |
| `依赖` | 哪些单元必须先懂 |
| `留下的新问题` | 这个单元结束时，学生自然会问的下一个问题 |

**切分规则**：

- 单元边界 = 材料**答完一个问题、正转向另一个问题**的位置，**不是**标题位置、不是时间戳位置。
- 定义与它的首次使用在材料中一口气出现 → 算**一个**单元。
- 公式与它的推导：推导短（不需要引入新量）→ 一个单元；推导引入了一个本身需要动机的新量 → 拆开。
- 例子 / 实验 / 数据集样例 → **附着**到它所服务的那个单元，不单独升级为单元。

### B. 问题链

把每个单元的 `对象` 改写成**疑问句**，再按「学生此刻会问的下一个问题是什么」把单元连成 DAG。

> **这一步是最关键的一步，也是最容易被跳过的一步。**
> 用名词短语命名单元（"SFT 数据"、"FLAN"、"PPO"）就是按标题切分的根源——名词是**主题**，疑问是**认知任务**，两者的边界不一样。

产出两个候选集合：

- **合并候选**：两个单元的问题同义（问的是同一件事）。
- **拆分候选**：一个单元回答了两个可以分别独立提出的问题。

### C. 合并 / 拆分判定

对每个候选和每个单元跑四条测试：

| 测试 | 判据 | 结论 |
|---|---|---|
| **合并测试** | U1、U2 答同一问题；或 U2 是 U1 答案中**不可独立成问**的必要子步骤 | 合并。若 U2 能被独立提问且在 U1 缺席时也能讲 → **不合并** |
| **拆分测试** | 能同时写出两句都真、且互不蕴含的「本节其实就是：X」和「本节其实就是：Y」 | 拆成两节 |
| **删除测试** | 删掉它，其余每一节的核心问题**仍然可答** | 它不是知识主线 → 送 Stage E |
| **原子性判据** | 「这一节其实就是：___」只有唯一一个正确填法，不存在第二个同样为真且独立的候选 | 通过才允许定稿 |

### D. 依赖排序

- 用 Stage A 的 `依赖` 边建 DAG，拓扑排序。
- **源顺序只能当 tiebreaker，不能当约束。** 材料可以为了叙事把一个概念的使用放在它的动机之前；教学不能。
- **破环**：若 A 依赖 B、B 又依赖 A，二选一——
  - 把其中一方拆出一个最小前置（"先只需要知道这个直觉"），或
  - 降级为「先记住结论，第 N 节再解释」，并记入**承诺点**（含兑付节号）。
- **忠实度约束**：每个单元携带源位置；重排后必须能验证
  - 没有内容被丢掉；
  - 没有改写讲师的原结论；
  - 没有把自己的理解冒充课程结论。

### E. 旁支分流

所有非主线单元，归入**恰好一个**桶：

| 桶 | 判据 |
|---|---|
| `删除` | 对任何一节的核心问题都没有帮助 |
| `后置节` | 它本身是个独立问题，只是前置尚未具备 → 后面单独立节 |
| `一句提示` | 正文里一句话带过，不展开 |
| `附录备查` | 有用，但不是教学内容 |

逐单元记录归属。这是"有没有为了完整而塞旁支"的**可审计证据**。

### F. 粒度校准

目标区间 **15–30 节**。

- **超过 30**：找相邻的、答同一问题或构成纯前置链（中间没有独立疑问）的节 → 合并。
- **不足 15**：用拆分测试找隐藏的多问题节；特别检查**材料本身写得简略**的地方——模型常因原文一带而过而漏拆。
- **例外**：材料本身就短，允许少于 15 节。**明确声明例外，不要注水凑数。**
- **超长材料（多讲 / 整学期）**：先按"讲"分组，每一讲独立跑 A–G；讲与讲之间只记录「前置讲」，不跨讲重排。

### G. 产出

按第 1 节的契约输出四件东西。路线图示例见 §6。

## 3. 拆节自检

定稿前逐项回答，**每项必须给出"是/否 + 证据"**，不能只写"是"：

1. 每一节能否用**唯一一句**自然语言概括？是否存在第二个同样为真且独立的候选？
2. 有没有两节的核心问题可以**互换而不影响理解**？（可以 → 它们其实是一节）
3. 去掉任意一节，后面是否就讲不通？（讲得通 → 它不是真前置，是凑数）
4. 有没有哪一节的核心问题**依赖一个尚未出现的概念**？（有 → 排序错，回 Stage D）
5. 路线图里的每一节能否在材料里**找到出处**？（不能 → 可能是自己补的，需标记「补充：」或删除）
6. 每一个原子单元都**有归属**吗？（覆盖核对表总数守恒）
7. 有没有哪一节的「**本节不做什么**」是空的？（空 → 边界未定义）

## 4. 失败模式目录

每条都附**真实事故**或真实产物证据，不是想象出来的。编号供 `SKILL.md` §7 引用。

| 编号 | 失败模式 | 证据 | 修正动作 |
|---|---|---|---|
| **FM-1** | 主线没先钉死就展开多层次旁支，主旨被稀释 | 一次真实教学中讲者的自诊断：「每一小段都没错，但读完之后主旨反而被稀释了」——实际想讲的核心只有一句，却过早展开了 loss、长度偏差、benchmark、preference evaluation 等多个层次 | 写正文前先写出本节唯一一句话核心，再逐段检查是否支撑它 |
| **FM-2** | 局部因果关系被做成"板书公式" | 用户原话：「`long SFT data` 这些情况没必要单独占一行」；讲者自述：「会让内容产生一种讲义腔、板书腔，阅读节奏被人为切碎」 | 普通因果进句子；只有真正需要建立结构关系时才单独展示 |
| **FM-3** | 把"讲完整"误当成"每个相关概念都展开" | 讲者自述：「我前面有点把『我要把材料讲完整』误当成了『我要把每个相关概念都在这一节展开』。这就很像你说的古板讲师——担心漏点，于是不断加旁支、加定义、加公式」 | 旁支检查：学生现在不懂它，会妨碍当前核心认识吗？不会就不讲 |
| **FM-4** | 路线图条目混用名词短语与疑问句 | 一份公认不错的真实路线图里仍有「FLAN：早期 Instruction Tuning」「OpenAssistant → Nemotron：从聊天到 Agent 数据」这种名词型条目，与「为什么 Pretraining 之后还不够？」混排 | Stage B 强制疑问句；路线图里出现名词型条目 → 回炉 |
| **FM-5** | 用户跳节时无规则可依 | 真实教学中用户直接说「从第七节开始讲」，而规范只写了"路线图之后只正式讲第 1 节" | 见 `SKILL.md` §5 任意入口规则 |

## 5. Worked example：Stanford CS336 Lecture 15

**材料**：`chapter-books/stanford-cs336/lecture-15.md`
**钉住的版本**：commit `14a67918e3a4e6e98d2b346b29518fe12e8d9cd7`
**原始规模**：45,363 字符；68 个 `##` 节点 = 2 个前后言 + **65 个内容节点** + 1 个参考链接
**公认产出**：**22 节**

### 5.1 反例：按节点切（不要这样）

直接拿 65 个节点当 65 节，或者按 `00:00:08` / `00:06:46` 这类时间戳切。后果：

- 节点 7「SFT 的两个成分：训练数据与方法」和节点 9「开源 SFT 数据演进」被切成两节，但它们回答的是同一个问题——**过度拆分**。
- 节点 10–13「FLAN 随机样例 / Alpaca 随机样例 / OpenAssistant 随机样例 / Nemotron 随机样例」是**四个平行样例**，按节点切会得到四节无差别罗列；真正的认知结构是**三代数据生成范式**（人工众包模板 → 模型自生成 → 聊天/Agent 场景数据）——**该合并且重排的地方被平铺了**。
- 节点 17–18（偏好评估的长度/风格效应，00:20）与节点 48（RLHF 与长度效应，01:04）**在原材料里相隔 44 分钟**，但它们是同一个认知问题的两面。按时间戳切会把它们永远分开。

## 6. 边界情况

| 情况 | 处理 |
|---|---|
| 材料短（< 15 节） | 允许，明确声明例外，不注水 |
| 材料超长（多讲/整学期） | 先按讲分组，每讲独立跑 A–G；讲间只记"前置讲" |
| 连续转录稿（无任何小标题） | 边界必须自己找；**禁止拿时间戳当边界** |
| 教科书型材料（本身按主题分章） | 最容易直接按章切 → 必须先做 Stage B 再切 |
| 材料含大量代码 | 代码归属到它实现的公式所在单元 |
| 依赖成环 | 破环 + 记承诺点（含兑付节号） |
| 材料本身有错/缺失 | 用「补充：」标记，**不改写原结论** |
| 同一问题在材料中分散多处 | 跨源位置合并；源位置列写全 |
