## [2.1.2] — 补上「标签行 + 内容行」这种漏网的板书腔；进度行改固定格式

**变更类型**：排版规则补漏 + 输出格式收紧。两条均来自用户带着截图的具体反馈。

### 缺陷 1：FM-2 只点名了「因果 + 箭头」，漏了「标签行 + 内容行」

用户截图里的排版：

```
也就是：
        log P_θ(y|x)
乘上：
        A
得到：
        A log P_θ(y|x)
直觉：
如果：
        A > 0
那么：
增加：
        P(y|x)
```

2.1.1 的 §1.5.6 已经禁止「普通英文短语 / 简单因果关系 / 伪公式」独占一行，但**没有点名这种形态**：每个标签（`也就是：` `乘上：` `得到：` `直觉：` `如果：` `那么：` `增加：`）独占一行、内容另起一行。它本质上**是把一张两列表格竖着写**，所以不触发原有措辞。用户给出的正确形态：`如果：A>0，那么：增加：P(y|x)` —— **凑成一行**。

### 缺陷 2：进度行被塞进元话语，且丢了总数

实际输出：

```
进度：Lecture 16 第 2 节｜路线图已按新版规范开始重新校准，后续节号会以新版拆分结果为准。
```

两个问题：**没有总数**（学生不知道还剩多少），以及**混进了过程说明**（进度行不是汇报工作进展的地方）。用户要求：`进度：Lecture 16 第 2 节｜共 23 节`

### 修改

| 修改 | 位置 |
|---|---|
| 新增「**标签行 + 内容行**」禁令，含 ✗/✓ 对照与判断标准（某行只有两三个词或只是光标签，内容在下一行 → 合并） | `SKILL.md` §1.5.6 |
| 进度行改为**固定格式** `进度：Lecture 16 第 2 节｜共 23 节`；明确「只写第几节和共几节两个数，不得塞解释、校准说明或元话语」；附反例 | `SKILL.md` §5.1 |
| 排版检查增加「标签行 + 内容行」与「短条件句是否凑成一行」 | `SKILL.md` §7.2 |
| 结尾检查增加「进度是否为固定格式且无附加说明」 | `SKILL.md` §7.2 |
| FM-2 补上新变体与证据（含截图中的排版原文） | `section-splitting.md` §4 |
| 同步提示词：排版段补标签行禁令、进度格式改为新格式 | `prompts/chat-mode.md` |

## [2.1.1] — 修掉 FM-7：节末四件套被节内小检查挤掉

**变更类型**：收尾契约收紧 + 修掉 2.1.0 自己引入的术语撞车。触发原因：某节被反馈「太紧凑」后**重新生成**，结尾只剩下一个「小检查」+「我先停在这里，等你回答这个问题，再进入下一步」——**进度**与**下一节预告**都消失了，而它的**上一版四件齐全**。

### 根因（两条，其中一条是本仓库自己造成的）

1. **规范把第 4 项标为「可选但推荐」。** 模型据此合法省略。同理，§5.1 用「默认包含四部分」这种软措辞，也给了省略空间。
2. **2.1.0 新引入的「拍点小检查」与节末「理解检查」术语撞车。** 这是**本仓库在 2.1.0 造成的回归**：§1.5.8 写下"拍点之间要有停顿、例子、反例或小检查"后，模型把节内的「小检查」当成了节末的「理解检查」，用小检查顶替了整个收尾块。写规则时没有检查新术语是否与既有术语冲突——这正是 `references/skill-maintenance.md` §3「反馈先抽象，再全文扫描」要防的那类问题，而这次是我自己犯的。

### 新增

| 新增 | 位置 | 说明 |
|---|---|---|
| **FM-7** | `section-splitting.md` §4 | 节末四件套被节内小检查挤掉；记录触发条件是"可选"措辞 + 术语撞车 |
| **重生成规则** | `SKILL.md` §5.1 | 「重新生成第 N 节」时仍须完整走节内结构 + 节末四件套，不得因为"只是重讲"省略收尾 |
| **拍点小检查 ≠ 节末理解检查** | `SKILL.md` §1.5.8 + §5.1 | 小检查是节内装置（可多个）；理解检查是节末块（只 1 个，不可被替代） |

### 修改

- **§5.1 标题**：`每节结束的四件套` → `每节结束的四件套（缺一不可）`；「默认包含四部分」→「**四件都必须出现，顺序固定，写在所有教学拍点之后**」
- **第 4 项去掉了「可选但推荐」**，并明确：只有用户明确说「不要预告」时才可省略。理由写进了正文——*进度和预告是学生判断"我在哪、接下来去哪"的唯一依据*
- **§7.2 结尾检查**：由「是否只有本节总结、进度、一个理解检查…」改为「四件套是否**齐全**？是否写在所有拍点**之后**？**缺任何一件都算这一节未完成**，不得停止」

## [2.1.0] — 修掉 FM-6：拆节对了，但单节被压成高密度讲义

**变更类型**：判定规则增强 + 新增失败模式。触发原因：一次真实使用中，模型**正确执行了** 2.0.0 的拆节流程（24 节路线图、六列、覆盖核对表、承诺点清单、四件套结尾全部到位），但用户反馈**「太紧凑了」**。

模型自述原因：

> 这一节我原来实际上塞了至少 **3 个可教学的小块**：`reward model 是代理目标`、`为什么会 overoptimize`、`RLVR 为什么是一个不同方向`。
> 现在这个版本更像"高密度讲义"，而不是"私人导师授课"。

### 根因（两条 skill 缺陷）

1. **原子性判据不查复合疑问。** 该节核心问题写成「RLHF 的 overoptimization 为什么让 RL 难以继续 scaling，**而** verifiable reward 改变了什么？」——**表面是一句话**（所以"能否一句话说清"放行），实际是用「而」并列的两个疑问。写作时被迫承载两个认知任务。
2. **反旁支规则被过度应用成"越短越好"。** 2.0.0 有 §1.5.3（不要横向铺开）和 §1.5.7（不需要证明自己很完整），但**没有反向约束**：`旁支`（该删）与`教学拍点`（该展开）没有被区分，于是必需的推进步骤也被压掉了。

### 新增

| 新增 | 位置 | 说明 |
|---|---|---|
| **复合疑问检测** | `section-splitting.md` Stage C | 核心问题里用「而 / 并且 / 以及 / 同时 / 又」并列两个独立疑问 → 不合格，必须拆 |
| **拍点计数** | `section-splitting.md` Stage C | 回答核心问题需要几个互不重叠的新概念？2–4 正常，**≥5 说明核心问题其实是复合的** |
| **教学拍点 / 旁支 的定义与区分** | `section-splitting.md` Stage C + `SKILL.md` §1.5.8 | 拍点要**展开**，旁支要**删**——反旁支 ≠ 越短越好 |
| **§1.5.8 展开拍点，不要压缩** | `SKILL.md` | 给出判断标准（"获得新认识"还是"只看到很多信息"）与停止条件（核心问题答完，不是写得短） |
| **FM-6** | `section-splitting.md` §4 | 单节原子性通过但多个拍点被压成连续几段 |
| **源位置列格式约束** | `SKILL.md` §1.2 | 只写节点编号/页码/时间戳，不要把引用标记塞进表格单元格 |

### 修改

- **拆节自检 7 项 → 9 项**：新增「这一节的『一句话』里有没有并列的两个疑问？」与「回答这一节的核心问题需要几个教学拍点？」

- **§1.5.3 增加反向警示**：明确指出把该规则用成"越短越好"是错误的，并指向 §1.5.8
- **§1.2 硬性要求 3 条 → 4 条**：复合疑问禁令升格为与"疑问句"、"本节不做什么"同级的硬约束

## [v3.2] — 技术历史锚点增补

**新增一个核心原则**：新的算法、数据集、模型、benchmark、重要论文或训练方法**第一次正式出现**时，用极短篇幅交代"什么时候、谁、为什么出现"，把技术概念挂到真实发展背景上。

同时继续遵守 v3.1 最重要的限制：**历史背景必须服务当前认知问题；如果开始喧宾夺主，就应该停止。**

关键子规则：

- 历史锚点默认只占 **1–3 句话**；判断标准是"删掉以后会不会少一个有用的记忆坐标"。
- **先讲当前问题，再补历史**，不要反过来报家谱。
- 必须区分**提出 / 发表 / 发布 / 训练 / 开源 / 首次应用 / 推广**。
- 背景事实不确定时**必须查原始来源**，不凭印象补充。
- 同一对象**只在第一次正式出现时**建立锚点。
- 算法要说明"**它为什么在那个时间点出现**"；数据集讲"填补了什么缺口"；模型放回当时的技术路线。
- 不破坏 v3.1 的"单节聚焦"：历史信息同样要过旁支检查。

其余规则全部直接继承 v3.1。

## [v3.1] — 教学表达与单节聚焦增补

v3.1 相比 v3 主要新增四个约束：

1. 先把一句最简单的话讲清楚，再系统化。
2. 一节不只是"一个主题"，而必须只解决"**一个认知问题**"。
3. 避免短语、箭头、方框泛滥造成**板书腔**；普通逻辑用正常语言表达。
4. 课程教学以**学生问题的自然推进**为组织方式，而不是以教师知识分类的完整性为组织方式。

逐条要点：单节主轴测试；先让学生"看见区别"再给抽象概念；优先讲"最简单的真实意思"；禁止为了完整在单节内部横向铺开；控制板书腔与纵向碎片化排版；不要用"讲得系统"冒充"讲得好"；重要区别优先采用对照教学；公式必须解决语言已解释不清的问题；课程材料决定讲什么、教学逻辑决定怎么讲；一节不需要"证明自己很完整"；结尾总结压回最朴素的核心；理解检查只测本节那个"关键区别"；输出前的教学压缩检查；用户反馈触发的即时校正。

## [v3] — 单节信息边界与来源规则

v3 的主要新增：

- **最高优先级：单节信息边界**。第 N 节只允许包含理解第 N 节必需的内容；引入**删除测试**。
- **禁止跨节抢跑**，并明确禁止"顺便讲一点后面的内容"句式。
- **下一节预告**被明确允许，但只能是"钩子"（1–2 句，只提问题）。
- **新概念首次引入时补充"来源与时间"**：谁 / 什么时候 / 必要时论文名或会议名；来源必须可靠，不确定就明确不确定。
- 新增 **Reference Registry** 与**执行前快速检查**。
- 新增 **Skill 自更新能力**，引用《Skill 更新、博客化与外部知识资产原则》。

## [v2] — 基础规范

v2 是完整自洽的基础版，确立了：

- 角色设定与首要原则「**课程材料决定主线**」。
- 学习目标：不是快速总结，而是建立连续知识结构。
- 开课流程：完整阅读 → 认知依赖切分 → 15–30 节主干路线 → 只讲第 1 节。
- 单节七构件：问题 / 直觉 / 玩具数字例子 / 数学 / 真实课程案例 / 常见混淆 / 前后连接。
- 节奏控制最高优先级：**严格控制知识前置与剧透**。
- 数学"先机制后公式"；代码"最小必要 + 公式与代码行对应"。
- 对课程材料的忠实度，课程外知识必须标记 `补充：`。
- 每节结束三件套：一句话总结 / 进度 / 理解检查。
- 中途提问保持位置；发现讲早了要显式回退；整讲结束时才允许整体串联。

> 上游 v2 原文未提供 v1 链接，因此 v2 被视为基准版本。
